## 链路与状态

手机 PushManager 订阅 → 认证后的 Pocket HTTP API → Mac 私有订阅表。Mac `Notifications` 读取原 owner 历史中的 turn/请求状态变化，使用 web-push 3.6.7、VAPID、aes128gcm 发送至 Apple/Google/Mozilla 的 Web Push 服务。Service Worker 显示通知，点击后优先发送任务 ID 给现有页面并等待 ACK，保留正常页面草稿；没有页面或离线壳不能响应时打开带任务参数的 URL，登录后进入目标任务；启动重试保留这个参数。

11-08 入口完善：现有窗口只复用正确电脑的主应用窗口，排除嵌套预览、独立HTML和无关同源页面；不导航或重载旧窗口。已在目录里的目标先进入，再后台同步，弱网同步失败不阻止查看；暂未同步的目标保留，成功读回后进入，后来的用户选择不会被迟到同步抢走。登录前收到的通知仅记录合法target与当时task路由维度（机器隔离），不存完整URL或未知参数；同旧路由登录后可进入新通知会话，新的显式task URL优先。存储被禁且App尚未接收时不ACK，交给SW在新窗口用目标URL恢复。

会话名清理控制/换行并限制120个Unicode字符，缺失时回退Pocket；名称取实际发送时的当前值，旧通知负载没有名字仍兼容。名字可能出现在系统通知或锁屏上，这一展示来自11-08用户的明确选择；无新增正文预览或遥测字段。上线身份、两机后端与真机验收状态回CURRENT。

它是 Web Push，不是浏览器定时器保活。Mac 仍需在线、唤醒、Pocket 服务运行。首次在 iPhone 主屏幕 App 中点击开启并允许系统通知必须在实际设备完成，服务端准备好不等于手机已收到。

- 只在实时桌面快照上判定完成/失败；保存历史回退或读取错误不推断完成。
- 首次打开不重放旧完成/旧问题；新发送被原 owner 接收后也建立跟踪，覆盖未等到历史读取就离开页面的情况；新请求按稳定指纹去重。已经处理的请求会取消未发提醒，重试前也重读原 owner。
- 10 秒调度，单轮最多检查 4 个近期任务；不是实时流式通知。读取失败仍轮转，避免一个离线任务阻塞所有任务；fallback 保留待核验的源版本。
- 最多保留 100 个最近打开任务，7 天未再打开或发送则停止关注。订阅设备最多 10 个，30 天未重新登记则失效。需要更大范围时单独调整，不默默扫描所有历史任务。
- 发送失败最多尝试 3 次；404/410 移除失效订阅。待发事件超过 10 分钟作过期处理，服务端推送 TTL 120 秒；同一事件 tag 用于系统通知合并。推送服务接受不等于设备已呈现。
- 退出登录会删除当前订阅并调用浏览器 unsubscribe；轮换 Pocket 口令会清空所有通知订阅和待发事件。

## 私有数据

VAPID 密钥位于 Application Support/CodexNavigator/web-push-keys.json（0600），自动生成并复用，不随发布轮换。订阅 endpoint/加密 key、状态指纹、待发回执存 Pocket 私有 SQLite，不进入整理备份或 Service Worker cache。允许的订阅端点仅为 HTTPS Apple Push、FCM 和 Mozilla Push 主机，拒绝任意 URL、端口和凭据，避免让订阅接口变成网络代理。

认证接口：GET /api/notifications；POST/DELETE /api/notifications/subscription；POST /api/notifications/state。写入沿用同源、Cookie/本机 CLI 与 CSRF 边界。外网仍不能使用 loopback CLI token。
