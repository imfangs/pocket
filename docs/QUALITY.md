# 手机远控持续打磨

2026-09-28 方帅要求持续打磨远控，让它顺滑。目标入口是 iPhone 添加到主屏幕后的 x.fangs.cc；返回手势是从左边缘向右滑。

## 每次接续

本记录用于有明确任务时的开发接续；自动化的当前状态只在 [CURRENT.md](../CURRENT.md) 的“继续方式”维护。先读该页和最新用户反馈，核对工作区；涉及运行或发布时再核对线上版本。选择一个有真实摩擦或验证缺口的完整流程，取得基线，完成相称的改动、回归和真实回读，再按任务范围发布。没有值得改的事项时保持现状，不因旧记录恢复定时执行。

遇到整体减法或同类冗余的再次纠正，先按[迭代复盘第4、6节](research/2026-10-11-pocket-interaction-retrospective.md)审视同一路径的相邻常驻区域，明确本轮覆盖范围与保留理由，再统一实施；不用每次等待用户点名下一个控件。

改善现有读取、发送、恢复和移动交互；原任务新建/管理与共享队列需区分已有授权和接口可用性，见 CURRENT.md。真实执行继续交给原 owner，并保留原审批与权限语义。任务数据、历史和草稿不进入公开构建、Git 或第三方模型。每次发布保持可回退并保留源码/部署身份。

UI 组件引入先读 [AI Elements 适用性评估](research/2026-09-28-ai-elements-fit.md)：研究阶段建议先隔离验证 MessageResponse；本轮视觉打磨采用 Radix Popover + Sonner，保留现有 Markdown / 输入 / 队列，具体取舍见 [视觉系统](design/2026-09-28-pocket-polish.md)。

调研候选的执行边界见 AGENTS.md；两项已完成外部调研的采用判断见 [2026-09-29 调研输入](research/2026-09-29-external-research-intake.md)。研究基线中的停止、异步问题和恢复已有增量实现；下一次大规模补功能前，先比较官方 Remote 的实际账号可用性与现有任务覆盖，不能仅凭官方说明判定替代效果。

## 已建立的验收基线

- **iOS主屏幕原生渲染**：系统scroll edge effect不属于网页CSS，桌面WebKit的`filter:none`不能排除它。用simctl等原生截图覆盖实际PWA，并确认`navigator.standalone`；以已知清晰状态对照，避免启动时就已异常却因前后相同而误判。10-30已用新的document做A→B→A，再以无注入最终包复验新建关闭和详情返回，见[顶部模糊修复](design/2026-10-30-ios-header-scroll-edge.md)。截图前核对弹窗/详情确实关闭，不能把系统键盘动画中漏点的遮罩帧当成渲染差异。

- 使用分析与其他外联能力按下方[使用反馈验收](#使用反馈验收)核对正式入口约束及数据入库；资源哈希通过不能代替采集成功。

- 合成测试通过 `npm test` 运行，入口会阻断真实原生 opener；定向测试使用 `node --import ./tests/helpers/block-native-open.mjs --test tests/<name>.test.mjs`。`makeApp` fixture 显式注入 `openThread`，需要已恢复 owner 时返回 `source: 'desktop', resumeState: 'resumed'`；不能让假 thread ID 打开用户桌面。来源与覆盖边界见[10-18恢复报错排查](research/2026-10-18-codex-rollout-test-isolation.md)。

- 公网可达性需区分探针与实际浏览器：09-30 urllib返回Cloudflare403/1010，而curl和手机尺寸浏览器正常。具体回读见CURRENT.md的18:04记录；单一探针失败先对照正常访问路径，不直接当成Pocket故障或据此重启、发布。

- 刷新/输入连续性：2026-09-30复现并修复旧目录覆盖新结果和已保存说明、迟到发送回执影响重进后的新草稿、输入框长高时底部阅读滞后。合成手机/桌面验收、168项检查与边界见 `docs/design/2026-09-30-steady-interaction.md`，发布状态见CURRENT.md。后续改动需保留原requestId核对和向上阅读的位置，不以取消前端轮询当作取消已提交任务。

- 长会话发送：2026-09-30复现约29MB桌面快照的两次核验耗时18.15秒，超过原16秒总上限。已增加短HTTP回执、只读轮询、普通发送45秒预算与发送阶段判别；隔离18.5秒慢连接流程通过。真实发布/回显及未解决的隧道波动见CURRENT.md和 `docs/design/2026-09-30-send-reliability.md`。

- 前台恢复认证时序：较早的未登录响应不能覆盖后续成功登录；较早的已登录响应不能覆盖退出或明确过期。隔离390px浏览器已复现并修复草稿丢失，实际发布和真机边界见 CURRENT.md 与 `docs/design/2026-09-29-access-resume.md`。

- 队列与直接发送：公网受控任务实测运行中添加/编辑/删除；直接发送留在同一 turn，排队消息在 completed 后开启下一 turn，准确回显、0 工具调用、取消消息未执行、原归档已恢复。证据 `.local/qa/queue-live.json`。Pocket 与桌面待发列表独立；PWA 真机交互仍待验。

## 使用反馈验收

目标是验证真实操作能留下可查询、可关联的记录；产品效果仍需另有使用证据。来源与CSP漏验反证见[使用反馈记录](design/2026-10-26-usage-feedback.md#同日纠错正式-csp-拦截了上报)。

1. 浏览器fixture继承正式入口中影响行为的响应头，尤其CSP。携带相同JS而省略线上限制，不能代表正式环境；原生系统行为仍按真机边界处理。
2. 数据策略与代码一起核验：`tests/usage-csp.test.mjs`覆盖本机/Pages连接白名单及脚本、frame限制；`tests/usage-journal.test.mjs`覆盖时序、关联、前后台计时与失败隔离。发布的`bin/verify-public.mjs`实际回读首页策略及采集所需域名。
3. 对一个明确标为验收的操作，分别保留页面结果、请求/错误与PostHog独立查询回读。后端事件存在才确认已入库；查看回放时再区分有ID、有录制与实际能播放。正文/草稿与原任务行为的保护沿既有契约。
4. 回读按反馈ID配对记录并核对环境、时间和内容。人工从正式入口提交的验收仍是测试样本；保存其用途，后续分析不把它归为真实痛点。原被阻断的反馈与补交的反馈分别记录。

通过以上检查可以确认采集链路；发现问题频率、原因和改善效果，继续按[反馈复盘流程](design/2026-10-26-usage-feedback.md#查反馈与复盘的接续流程)取证。

反馈面板的视觉验收同时核对内容边距和外框：标题、截图、说明、输入与主按钮应落在同一内容边线；滚到底时按钮仍应留出底部安全区，关闭入口仍可见。覆盖320px窄屏、常规手机、桌面、亮暗主题与键盘缩小/偏移；图片内滚和标注坐标另外验证。10-29初版虽然通过流程与外框检查，但`section`漏接`form`的padding，留下1px贴边和被裁切的关闭按钮；该反证与修复见[反馈基础设施](design/2026-10-29-feedback-infrastructure.md#同日反馈弹窗的留白与滚动修正)。

共用交互的验证要跨完整事件序列：点控件的可见边缘，核对pointerdown、focus、pointerup、click期间位置；输入框把键盘交给问题/待发编辑区后，再点提交或停止。对busy/dirty原生dialog测试重复Escape、禁用/替换当前按钮后BODY焦点，以及嵌套层级；仅对已聚焦dialog发一次Escape不足以验证关闭保护。10-29的全路径反证与修复见[Impeccable精修](design/2026-10-29-impeccable-sweep.md)。

## 原生剪贴板验证

2026-10-26验证方法：模拟`readText`只验证应用接纳与保护逻辑，不能证明iOS系统Paste许可。使用一次性Simulator、合成文本和本地fixture，先隔离剪贴板自动共享；不要读取或覆盖Mac真实剪贴板。记录调用前/返回、Promise结果、modal/focus、input/change和最终字段长度，区分许可拒绝、空文本与应用丢弃。

本次`agent-device`的XCUITest驱动不能完成系统Paste交互。普通菜单可用原生AX导航；系统Paste改用已安装的固定版本`serve-sim`镜像与HID真实点击，先确认真实画面，再以本地OCR的单词框定位。不要通过修改隐私许可或模拟API结果让检查通过。主屏幕验证必须回读`display-mode: standalone`及`navigator.standalone`，安装入口可见不等于独立Web App已经启动。

每次结束按精确UDID停止镜像helper、停删本次设备，再恢复原剪贴板共享配置并回读；不删预先存在的runtime或其他任务的设备。2026-10-26的工具版本、事件与清理证据在`.local/qa/creation-clipboard-2026-10-26/`。

## 受控发送验收

只有发送/桥接相关改动或链路异常需要时才运行，不把每日回显变成任务污染。默认真实验证保持只读或操作可恢复的 Pocket 元数据。

需要真实模型回显时，使用 `.local/qa/remote-echo.json` 已记录的相关验收对象，先核对它没有运行/待审批或新的人类工作。临时恢复原归档仅用于该次测试，完成后恢复。文本只要求回复唯一标记，明确禁止调用工具、修改文件、发布文档或外发消息。提交前落盘 requestId，重复运行先检查回执与原历史；未知结果不重发。不以接收回执代替模型完成，也不把单次 API 回显升级为 PWA 真机发送或长期可靠性验收。

附件发送改动沿用同一受控对象。图片验收把随机标记只画在像素中，文件名和Query不包含答案；普通文件验收把另一标记只写入人工生成的测试文件，允许仅为读取这些附件所需的只读工具操作，其余修改、发布和外发仍禁止。核对答案、准确requestId、原轮completed及实际工具范围；保留模型仍引用的验收文件，不把上传成功或看到文件名当作模型已读取。附件证据入口为 `.local/qa/attachments-2026-10-10/`。
