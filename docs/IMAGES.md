# 会话中的本地图片

从手机选图或文件并发送到原会话，读[附件发送](design/2026-10-10-attachments.md)。该上传使用独立的已绑定附件记录，不扩大本文已有Markdown图片的任意路径权限。

Mermaid围栏生成的图表按[会话图表](design/2026-10-19-mermaid.md)的独立渲染边界处理，不因此开放本地SVG文件或外站图片读取。

2026-09-29，用户希望在 Pocket 查看已有任务最终回复中的图片。本轮以指定任务的两张 31 表情总览 JPG 为实际对象；每张约 0.5–0.6 MB，原尺寸均为 1680×2857。

## 范围与成本

支持可见 Markdown 正文里实际引用、位于原任务 cwd 内的本地 PNG/JPG/WebP/GIF。无需重新生图、云图床或转码服务，沿现有 Mac → 隧道 → 已登录网页传输。预览懒加载，点开使用[会话内大图查看层](design/2026-10-15-image-viewer.md)，右上固定“× 关闭”，同一条消息的图片可左右切换；支持缩放和拖动；图片失败时可单独重试。预留固定画框，避免图片解码后改变历史布局。

2026-10-22 补充：普通本地文件链接及 Codex 文件输出组件可以按点击下载，见[消息组件](design/2026-10-22-message-components.md)；下列格式限制继续用于图片内嵌预览。

正文图片预览传输原文件，不生成小缩略图；上传附件另有缩略预览。正文图片单文件上限8 MiB、一次历史最多32张、内存引用最多256个，Markdown解析缓存128条。2026-11-12新增[私有图片缓存](design/2026-11-12-upload-pipeline-and-image-cache.md#图片缓存与访问证明)：L1 12MiB、IndexedDB 64MiB、8路读取，有SHA和当前认证／来源证明才持久复用；附件原图20MiB边界保持，大于8MiB不落图片磁盘缓存。实际网络流量取决于缓存命中、查看数量和原图大小。外部图片继续显示链接，任务目录外的图片文件不开放；SVG／HTML／ZIP等普通文件沿[常见文件预览](design/2026-11-12-common-file-previews.md)各自的受控通道处理。视频使用独立的[文件流与原生播放器](design/2026-10-29-message-video.md)，不扩大本图片通道的格式或容量。

## 数据和访问契约

- 使用 Markdown AST 提取 image/imageReference；代码块、行内代码和普通文件链接不授予图片引用。解析器是现有 Markdown 栈已经使用的固定依赖，本轮仅显式声明为服务端直接依赖。
- 2026-10-28代码审查补充：只解析不超过128Ki字符且未标记`truncated`的完整消息，不先截字符串；否则闭合代码标记可能丢失并错误授予图片读取地址。重复引用定义采用第一条，与前端Markdown渲染一致。被截断消息暂不授予内嵌图片，原文字保留；验证与取舍见[代码质量记录](design/2026-10-28-code-quality.md)。
- 只有服务端返回的可见历史能登记引用。客户端收到与任务绑定的不可猜测图片地址，没有接受任意文件路径的读取接口。原消息文字保持不变。
- 图片 GET 继续经过既有 Cookie/本机认证、Host/Origin/跨站校验；任务身份、当前cwd、引用有效期也必须匹配。
- 读取时重新核对真实路径、任务目录归属、普通文件、文件大小和PNG/JPEG/GIF/WebP签名。拒绝逃出任务目录的符号链接、伪装图片、缺失文件和读取期间变动；限制实际分配/读取字节数。
- `no-store`、`nosniff`、同源资源策略和沙箱CSP随响应返回。退出后原图片地址401；图片没有加入 Service Worker 或公开构建。
- 引用只保存在当前服务进程内，闲置一小时或被有界缓存淘汰后，需要重新读取会话；服务重启后旧地址失效，下一次历史读取发出新的地址。

## Mac 文件访问权限

Codex 能显示图片，不代表 Pocket 后台服务也能读取原文件。macOS 分别检查前台应用与 LaunchAgent 的访问权限；会话目录在 `~/Documents/` 等受保护位置时，后台 Node 可能被隐私控制拒绝，即使用户、路径、文件格式与目录归属都正确。普通工作目录的图片不一定触发同一项目录权限。

先核对实际会话 cwd、图片引用、文件存在与容量，再检查已登记图片地址的 HTTP 结果。权限错误 `EPERM/EACCES` 返回403和固定提示，不把原始路径、errno 或异常正文发到浏览器，也不将所有权限错误都断言为 TCC。其他缺失／不可读文件继续保留404；原目录、格式、变动和引用过期检查保持。

只有图片加载失败时才额外诊断一次原图片地址；诊断有时间／响应大小限制，重试、切换或卸载取消旧诊断，不扫描其他目录、不自动重复请求。图片卡原地显示权限原因并保留重试，不额外占用全页阅读空间。

确认 macOS 拒绝访问「文稿」后，在 Mac 的「系统设置 → 隐私与安全性 → 文件与文件夹」核对**实际后台程序**，允许对应文件夹访问。前台 Codex 的授权不能作为后台授权证据；Node 路径／版本变化后也应重新核对，不能仅凭升级猜测授权丢失。若程序没有出现在列表，先调查真实启动与系统授权入口，不直接修改 TCC 数据库或用开放所有文件路径替代授权。修复后重试同一图片，核对200、原始字节和正常解码；健康接口或 doctor 通过不代表这张图片可读。
