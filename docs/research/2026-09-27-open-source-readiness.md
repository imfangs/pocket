# Codex Navigator 开源准备度评估

日期：2026-09-27。代码基线：`a9cc9ce`。范围：当前仓库、可达 Git 历史、合成兼容性探测与公开同类研究。未改变运行服务、认证、任务数据或部署；未创建公共仓库或发布宣传内容。

## 判断

**核心模型具备通用性，当前交付尚不具备直接对外推广的独立使用能力。值得整理成 macOS 优先的开源 Alpha。** 不需要先做全平台、团队协作或完整远程执行器。第一关是另一名 Codex 桌面用户能够独立安装，找回并继续旧任务，且原数据始终不受修改。

通用的是“已有任务的归属＋用户明确的接续意图＋一句接续说明＋原任务入口”。仍然个人化的是安装、数据格式适配、手机连接与发布配置。影响力是待验证结果，不是代码公开后自然产生的结果。

## 当前证据

| 维度 | 当前事实 | 发布前动作 |
| --- | --- | --- |
| 产品模型 | `server/store.mjs`、`src/model.ts` 的分组树、多组归属、意图、备注、搜索和备份没有绑定某个个人项目 | 保留这套模型，使用合成数据展示完整接续流程 |
| 本地运行 | Node/React 服务可直接 `npm start`，基本服务不强依赖 FBT；常驻、HTTPS 和远程发布步骤依赖个人环境 | 提供不依赖 FBT 的标准启动说明，把作者环境作为可选集成 |
| 安装可复现性 | `package-lock.json` 的 118 个 resolved 地址全部指向公司 npm 镜像；`package.json` 未声明 engines，README 要求 Node 26 | 从公开 npm 源重建锁文件，声明实际验证的 Node 版本，干净环境执行安装/构建/启动 |
| Codex 兼容 | `server/source.mjs:7` 固定读取 `state_5.sqlite`，要求桌面 global-state 和 pinned 列表；只验证过本机记录的 App/Core 版本 | 增加来源诊断、已支持版本说明、可选字段降级和只读兼容样本；不承诺所有 Codex CLI/Desktop 版本 |
| 操作系统 | `/usr/bin/open`、macOS Application Support、Homebrew 可执行路径；不能宣称 Windows/Linux 支持 | 首版明确 macOS 桌面来源；跨平台作为后续验证，不作为首发前置 |
| 手机接入 | Worker 中固定 `x.fangs.cc`，relay/Pages 配置绑定个人账户、KV、域名、Wrangler 路径，tunnel 固定源端口与 cloudflared 路径 | 公共配置模板与个人部署分离，移动接入标为可选实验功能 |
| 开源交付 | 未有 LICENSE、CONTRIBUTING、SECURITY、CI；UI/README 以中文和个人接续记录为主 | 明确许可证（建议 MIT，先核对代码/素材权利和依赖声明）、最小贡献/问题模板、干净安装 CI、英文 README 与合成演示 |
| 实际效果 | 已验证运行、保存与恢复；没有外部用户连续使用证据，真机 PWA 也未验收 | 邀请目标使用者独立安装并试用一周，观察是否真正重新进入旧任务 |

`private: true` 仅阻止 npm 包误发布，不妨碍 GitHub 开源，本轮不把它当作公开仓库障碍。

### 合成兼容性探测

在系统临时目录新建最小 SQLite 与 JSON，调用当前只读适配器，结束后删除。未使用或更改真实 Codex 数据。

| 场景 | 结果 |
| --- | --- |
| 最小桌面状态（必需列、置顶数组存在） | 导入 1 条 fixture 成功 |
| 缺少桌面 global-state | ENOENT，导入失败 |
| global-state 缺少 pinned 数组 | “未能读取桌面置顶列表”，导入失败 |
| 仅存在另一个数据库文件名 `state_6.sqlite` | ERR_SQLITE_ERROR，导入失败 |

后三项用于验证当前代码边界，不表示某个真实 Codex 版本一定使用该文件名/格式。当前来源失败会保留旧缓存，但新用户没有旧缓存可用；应提供明确诊断和支持范围。

### 发布资料与敏感信息

对所有可达 Git blob 进行了当前已知口令、salt、口令哈希和本机 CLI token 的精确值扫描，未发现匹配。该结果不等于完整历史秘密审计，也不能证明无其他敏感材料。

仓库仍包含个人绝对路径、部署账户/namespace 标识、个人域名、真实使用记录。账户/namespace ID 不等于密钥，但公共模板不应绑定它们。真实任务截图、运行数据和凭据目前被忽略；公开前仍需核对历史和演示素材。对外演示采用虚构任务，不使用个人真实服务入口作为公共 demo。

lockfile 的许可证标签包括 MIT、Apache-2.0、ISC、BSD-3-Clause 和一项 CC-BY-4.0；这只是机器标签清点，不能替代发行时的依赖与素材声明检查。首版建议保留当前本地开发历史，从脱离个人部署的代码形成干净公开基线。

## 定位与传播实验

最新证据详见 [同类能力复核](2026-09-27-oss-landscape.md)。官方三条相关需求仍 open，证明存在其他明确提出问题的人；并不证明市场规模。Agent Sessions 已加入原 Codex Desktop 任务回跳，CodexMonitor 已有远程/iOS 方案，不能宣传这两个能力为独占创新。

建议对外一句话：**整理散落在 Codex 中的长期任务，记下下次从哪里继续。** 英文方向：*Organize your Codex threads and remember where to pick up.*

演示用一条 30–60 秒的完整动作链：杂乱列表 → 跨项目分组 → 标记稍后并留一句说明 → 下次找到 → 回到同一原任务。README 首屏同时说明只读 Codex 来源、整理信息独立保存、当前兼容版本与安装方式。

首轮先招募 5–10 名本来就有大量 Codex 任务的人，目标是验证：

1. 无作者代操作能否在自己的 Mac 安装并看到正确列表。
2. 保存几个明确想继续的任务后，一周内是否真的通过任务架重新进入过它们。
3. 用户是否愿意反复打开这个额外入口，整理是否变成负担。

优先用试用反馈与 issue 中的可复现问题判断价值；stars、曝光和访问量只说明关注。若用户仍只用官方侧栏，或者官方分组已足够，继续加面板功能未必有效；应考虑减少入口成本或向已有项目贡献接续功能。当前没有发布或招募行为。

## 建议的首发完成线

形成 `v0.1.0-alpha`：macOS 本地管理、标准安装、合成 demo、中英 README、LICENSE/必要声明、最小 CI、明确兼容范围；手机 PWA 单列实验接入。干净环境验收至少覆盖安装、读取、保存、重启、回到原任务、卸载后原数据保留。无需等发送指令/新建任务完成才能开源。

该方案尚未实施；本轮完成评估与证据沉淀，不把准备清单记为已实现。
