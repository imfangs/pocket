# 文件引用与消息组件的统一展示

2026-10-22。方帅反馈会话中出现 `:codex-file-citation{path="…" purpose="output"}` 原始标记，要求 Pocket 合理解析，同类组件保持统一。同期修正“仅显示最近的对话”不能区分上文读取和历史截断的问题。

## 用户看到的行为

文件引用和普通本地文件 Markdown 链接共用轻量文件入口，显示文件名与下载动作。只有点击才读取文件，下载失败在原入口下解释并允许重试；正文流式更新不会重建链接组件、中断下载或清掉错误。离开详情会中止尚未完成的下载。未登记或无法开放的本地引用显示名称和“文件保存在电脑上”，不暴露一段组件代码。

已有会话链接、代码批注、后续建议、批注编号和定时任务摘要保留。未知 `codex-*` 组件展示已有标题/正文和“此内容请在 Codex 查看”，不猜测其交互；流式未闭合组件先显示载入提示。用户原话、代码块、行内代码和转义示例保持字面量，组件本身不触发发送、执行或归档。复制与屏幕正文使用相同的展示转换。

## 文件数据通道

- `shared/codex-directives.mjs` 共用属性、代码/HTML保护和路径解析。拒绝重复属性、不完整引用、转义冒号、未知组件里的路径、URL/控制字符。真正 Markdown 本地链接支持一次 URI 解码，引用组件的路径保留字面。
- `MessageFiles` 仅从服务端返回的完整、可见 assistant 正文登记引用；用户内容、analysis 和已截断正文不签发文件能力。原消息不修改，额外返回 `files[原引用路径] = {name, url}`。
- URL 为 `/api/tasks/:threadId/files/:HMAC`，绑定当前会话和 cwd，无任意路径 GET。每次历史最多32个、进程最多256个、有效期1小时，解析缓存128项；正文超过128Ki字符不解析。
- 点击时重验当前会话目录、真实路径、普通文件、20MiB大小上限和读取前后路径/文件身份；符号链接逃逸、替换、变动或缺失返回安全错误。文件始终按附件下载，包含 HTML/SVG 时也不嵌入页面执行。
- 保留认证、Host/Origin/CSRF相关访问边界、no-store、nosniff、same-origin和沙箱CSP。前端核对当前thread和机器身份，拒绝伪造相对、绝对与内部render-token链接；下载流同样限制20MiB。
- 内容能力不是执行能力，不进入发送账本或共享桌面状态。切机沿用原机器路由和生命周期，不能跨机复用文件引用。

共享解析代码计入前端版本哈希，修改共享组件也会正确触发安全更新。暂不提供任意目录浏览、未引用文件读取、内嵌 Office 编辑器或全量附件同步。

## 上文提示

首次文字/原桌面双路读取尚未完成且已有部分正文时，提示“正在读取更早的消息…”。落定后确实还有未显示的历史，则提示“还有更早的消息未显示”；离线不再声称正在读取，常规轮询也不反复亮起首次加载提示。

边界信息跟随 `displayConversation` 实际选用的正文来源与裁剪结果。完整原生前缀到达后，旧 transcript 的 `hasMore` 不再把提示卡住。保留原有合并顺序和80条/16万字符上限，没有把 `hasMore` 当成后台正在全量翻页的承诺。
