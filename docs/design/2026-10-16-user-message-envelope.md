# 用户消息的浏览器上下文包装

2026-10-16。用户发现 Pocket 显示了 Codex App 不展示的 `My request:` 标题，并明确要求修复。

## 原因与修复

当前桌面会把浏览器页面状态和实际 Query 放进同一个 `user.text` 内容项：开头是带 `source="ambient-ui-state"` 的 `in-app-browser-context`，之后是 `## My request:` 和用户正文。它同时存在于原生快照与落盘历史中，provenance 不能直接将整个内容项当作注入信息删除。

Pocket 的 Markdown `skipHtml` 隐藏了前面的 HTML 块，但其后的 Markdown 标题仍被显示；复制时还会包含整个原始包装。

`src/userMessage.ts` 在 `ConversationMessage` 的用户显示投影中识别完整、位于消息开头的已知浏览器包装，包括准确的来源、固定说明、闭合标签以及紧随其后的一次请求分隔标题。确认匹配后仅移除前缀，正文原字节和换行保留，再沿用已有异步问题回答的可读投影。显示、复制和长 Query 收起使用同一投影。

原始 `message.text`、ID、来源合并、发送回执、已读观察、时间、附件与图片映射均不修改。此修复只需前端发布，不需要重启 Mac API 或 Codex。

## 识别边界

- 单独的 `My request:` 标题、正文中的说明、引用及代码示例不删除。
- Query 自己包含第二个同名标题时保留；不循环剥离。
- 来源或固定说明不匹配、包装不完整、包装与分隔标题之间出现正文时保留，不猜测。
- 支持已知格式的 LF/CRLF；不先 `trimStart()`，避免把四空格缩进代码当作运行时包装。
- 附件及 response-annotations 的处理仍沿用原有各自的规则，不因为出现同名标题就删除上下文。
