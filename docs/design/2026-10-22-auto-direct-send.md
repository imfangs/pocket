# 新消息优先直接发送

2026-10-22。用户要求设置增加默认开启的“自动直接发送”，并确认只影响开启后新提交的消息，旧待发消息不升级。

## 行为与归属

- 开关按当前设备和所选电脑保存，默认开启，同页及同源标签同步；储存不可用时本页选择仍可用。改变开关本身不发送消息。
- 点击发送时，真实桌面可接收、没有旧队列/暂停/读取失败则直发；运行中走原追加路径，空闲时开启下一轮。暂不可接收则排队。
- 普通 Query 和新建首 Query 都保存提交时的 `autoDirect` 意图。连接恢复、页面关闭或服务重启后，待发消息仍沿用原选择；后续切换开关不改已提交内容。
- 关闭开关保留原行为：空闲可发，运行中等待本轮结束。旧客户端缺省字段、旧数据库条目均为 false，原状态和 FIFO 顺序保留。
- 自动处理只看 queued 队首；编辑、拒绝、未知、整队暂停和未决操作不能被跳过。失败/中断轮次不自动重开；原“恢复排队”和手动“直接发送”继续表达明确用户动作。

## 协议与竞争边界

消息入口接受可选布尔 `autoDirect`；创建入口仅在有 `initialQuery` 时接受它。`dispatches.auto_direct` 默认0，与原请求ID一起保存；同ID不同意图返回409，不偷偷换策略。待发投影增加布尔标记，正文和附件仍用原账本/指纹。

后台仅在真实 desktop/active/canSend 时对已选择直发的队首用内部 `auto-now`。Python核验原owner及两次最新状态；如果中途空闲，仅 completed/empty 可继续，失败/中断/systemError不被自动接续。自动认领仅接受 queued，防止等待history时已变rejected却被重试；附件准备完成、进入bridge前再次检查暂停，避免停止后仍追加。

新意图的明确未发送就绪/连接失败可继续等待，结果未知只回读原ID。旧条目的失败语义保持。后台不因失联自行打开另一个owner；手动直发原权限、原模型/cwd/权限、附件绑定及创建时 `created + verified + processStopped` 约束不变。
