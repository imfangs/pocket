# 项目导航与智能排序

2026-10-14，方帅希望恢复菜单里的项目，只显示项目名字、点击改变主列表；以多类信号计算更顺手的列表顺序，减少手工筛选。随后明确加入 Pocket 近期新建、近期点击。

## 入口与取舍

历史核对：10-11 的 `50568cd` 删除的是由原项目生成的“我的分组”树，点击会改变主列表，侧栏本身没有展开会话条目；原项目一直留在 `ViewControls` 的筛选下拉。

沿用[10-08标杆记录](2026-10-08-notion-inspired-workspace.md)中 Notion 官方侧栏/视图机制：稳定的范围入口切换同一列表、当前范围可见。这是对已有来源的适配，没有声称本次实测了新版Notion界面。

- 菜单保留全部会话、原项目平铺、未归属项目、归档和设置。项目只显示名字，不放会话、数量、编辑或嵌套树。
- 原项目按 ID 识别和去重，排除来源分隔符项目；同名不同 ID 不错误合并，完整名称与路径保留在提示和可访问名称里。空项目保留入口；长名字省略不挤压底部功能。
- 点击项目进入它的全部会话，清搜索、关闭当前详情与手机菜单、列表回顶，标题直接显示项目名。全部会话明确清除项目，不冒充“返回上一范围”。选定项目在当前设备记住，成功读取目录确认项目已不存在时回到全部；读取失败不清除选择。
- 去掉“筛选”弹层、项目条件chip，以及菜单中重复的待输入/置顶/最近打开分类。主列表保留搜索和全局“待我输入 / 运行中”快捷入口；点击其返回按钮恢复原项目、搜索和阅读位置。
- 空项目不提供会暗中使用另一目录的创建CTA，改为查看全部会话。顶部新建仍沿用方帅原先“记住上次目录”的选择，不把浏览项目隐式变成创建归属。

## 排序规则

所有正常列表统一使用智能排序，不再因置顶、进入待输入或运行中而切换排列方式。归档页保留最近活动顺序。

同日方帅明确纠正：希望所有会话使用一条Rank公式，新建且活跃的普通会话应能超过长期没有消息的置顶。现已取消Pocket置顶硬层；两种置顶均为有限加分，排序器只比较总分。同分按最后消息、创建时间、固定ID收尾，置顶序号不再参与。Pocket明确取消置顶后不继承Codex置顶加分。来源缺失和分隔符记为-1分，保留记录但不冒充可操作会话。

| 信号 | 当前分值与边界 |
| --- | --- |
| Pocket有效置顶 | +90，与Codex置顶不叠加 |
| 明确等待回答或确认 | 新鲜运行状态 +180，不与完成未读重复计分 |
| 完成后待输入/未读 | 最高 +160，按7天尺度指数衰减；旧未读不会永久霸榜 |
| Codex有效置顶 | +60，Pocket false覆盖仍有效 |
| 有未提交草稿 | +85，仅按有/无，不按每次击键累积 |
| 正在运行 | 新鲜状态 +70，覆盖旧的完成未读快照 |
| 最后消息 | 最高 +100，按3天尺度衰减，排除设置同步/读取/工具等事件 |
| 会话创建时间 | 最高 +12，按2天尺度衰减，作为较弱信号 |
| Pocket近期创建 | 已确认创建回执最高 +45，按2天尺度衰减 |
| Pocket近期主动点击 | 最高 +55，按1天尺度衰减；反复点击不累计无限分值 |

这是可调整的产品启发式，不是概率或模型推断。得分相同按最后消息时间、创建时间、固定thread ID收尾；改变目录输入顺序不改变最终次序。非法时间不给分，未来时间钳到当前时钟。状态轮询的checkedAt不当活动时间；评分时钟随目录或真正的Pocket行为变化采样，不因每次状态轮询向前走。

“待我输入”的行状态、筛选、数量与排序统一口径：新鲜running不能继续吃旧needsInput；明确waiting_input/approval会被纳入；unknown不冒充idle，保留已有完成未读证据。

## 统一 Rank 公式

设 `f(t,k)=exp(-max(0,now-t)/(k天))`；时间不存在或无效时，该项为0。

```text
R = 90P + 60C + 180W + 160U·f(M,7) + 85D + 70A
    + 100f(M,3) + 12f(B,2) + 45f(PC,2) + 55f(PV,1)
```

- P/C：Pocket或Codex有效置顶，互斥0/1；false覆盖两项均0。
- W：当前确认等待回答/确认；U：已完成未读，运行/等待时不重复叠加。
- D：有未提交草稿；A：当前确认运行。均取0/1。
- M：最后可见用户/助手消息；B：原会话创建；PC：Pocket确认创建；PV：Pocket主动点击时间。

例：30天没消息的Pocket置顶约90分；刚创建且有新消息的普通会话约112分，运行中则约182分，后者会排在前面。置顶保留长期偏好意义，不保证固定位置；刚置顶一条旧会话也能得到完整的有限加分，不另猜逐条置顶时间。

## 消息时间与状态颜色

原`updated_at_ms`会被`thread_settings_applied`等内部设置事件刷新，不是最后消息，也不能当可靠的用户点击。本轮保留`updatedAt`作兼容元数据，列表时间、会话活跃度和排名平局均改用`lastMessageAt`。正在运行/等待时沿用原状态槽；显示时间时用最后消息，无法确认则显示“—”，不拿创建/访问/文件mtime替代。

`server/message-time.mjs`复用history的provenance、analysis和compacted隐藏规则；纯媒体也参与最后消息时间，但既有文字投影不变。路径和session_meta身份通过后，尾读64KiB，必要时扩到256KiB、1MiB、4MiB；预算内无结果则未知。4096项文件版本缓存只保存时间等元数据，未改变的文件不重复读正文。只读1500条实际来源的首读约1588ms、缓存后69ms，1489条取得时间；未知包含空/不可读或预算内无可见消息，不作为“刚刚”。

等待琥珀、未读蓝、运行绿以3×18px短线及原状态文字提示；Pocket红色轻填充图钉、Codex紫色空心图钉独立呈现。行底、行高、触控、左右滑和阅读锚保持。颜色是辅助信号，文字和可访问名称仍在。

## Pocket行为与隐私

点击只在用户主动激活列表行时记录。刷新、轮询、通知/恢复自动打开、切项目和返回视图都不记录点击。旧`lastOpenedAt`只代表在Mac打开/连接，不拿它冒充Pocket阅读历史；近期点击从此版本开始累积。

创建取已有操作账本中确认创建的threadId和原createdAt，包括“会话已创建、首条消息尚待确认”；仅有一个未知threadId不算确认创建。重复读取或恢复回执不续期原创建时间，不新增逐会话请求。

兴趣记录是当前设备的偏好，保存在`pocket.activity.v1`，仅有ID和创建/点击时间，最多200条；读取/写入时清理90天前的记录，不存Query、标题或正文，不改变Codex的活动时间、未读和置顶。存储不可用时本次页面仍可工作。缓存满时，被淘汰的旧创建重复到来不会制造新行为或刷新排序时钟。

## 列表连续性

向下阅读时保存第一条可见会话ID与相对位置。后台重排或从详情返回后按同一列表范围恢复，包含浏览器在DOM重排期间先把scrollTop钳到0的情况。用户自己回到顶部会清除这个锚点，让新优先内容自然出现在顶端。

“显示更多”的展开数量按最近10个项目/视图/搜索范围保留。后台新增/归档不会突然收回到80条；从运行中返回仍保留已展开数量与阅读位置。原草稿、消息、发送和管理回执不受排序影响。
