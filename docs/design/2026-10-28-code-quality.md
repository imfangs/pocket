## 已修复的问题

| P2 | `recoverConnection()`绕过历史缓存上限，合成120次不同会话连接保留120份历史，普通读取也不能及时收敛 | 两处写入统一到`DesktopService.cacheHistory()`，更新最近写入顺序并循环淘汰到10项；旧在途响应不得覆盖新连接快照。保持[架构](../ARCHITECTURE.md#阅读缓存与传输)的后端缓存边界 |
| P2 | 首屏空数组被视作历史基线；用户先提交“继续”，迟到首批历史中的旧“继续”会被当作新回显候选，新Query暂时出现在旧回答前面 | 等history/transcript两路首次成功读取，完整显示首批组合快照后才暂缓新候选；真实空会话仍可建立空基线，不比较跨机器时间。保留[发送连续性](2026-10-25-send-ui-continuity.md)的精确requestId与18秒回退 |
| P2 | 图片解析先截取24000字；闭合反引号在截断点后时，行内代码中的图片示例获得了读取地址 | 对不超过128Ki字符、未标记truncated的完整消息解析AST；不截字符串后重新解释权限。代码示例与被截断消息不授予图片能力，原文不改 |

上述问题均使用合成对象复现，没有调用真实会话发送、改名或归档。图片、缓存、认证和首读测试在修复前出现相应失败；修改后核验原失效场景与兼容边界。

## 维护性修改

- 为两处后端历史缓存写入建立一个小入口，避免连接恢复与普通读取的容量规则再次分叉。
- 认证代次与阅读缓存epoch保持独立；切换来源或清阅读缓存不能伪装为重新认证。
- 开启TypeScript的`noUnusedLocals`、`noUnusedParameters`，清除一处未使用的类型导入；不增加格式化工具、依赖或大范围文件拆分。

## 验证与交付边界

验证结果与本地提交状态在[CURRENT](../../CURRENT.md)维护；合成日志保存在`.local/qa/code-quality-2026-10-28/`。测试加载原生open拦截器，构建输出到同一隔离目录，避免替换正在提供服务的dist。浏览器使用现有Playwright和合成接口，未访问真实Pocket数据；此会话没有Browser插件，沿用已有项目验收入口。

独立复核另发现“登录响应头已到、JSON体未读完”的竞态，因此认证代次在动作开始时就更新，不能只在成功解析响应后更新。

保留的取舍：

- 任一路历史持续失败时不启用按同文暂缓，可能暂显两个记录；不能因此移动旧消息或确认发送。
- 已标记truncated或超过128Ki字符的消息暂不授予内嵌图片，即使图片引用在前段；源码和文字显示保留。这保护了无法确认完整Markdown语义的边界，并不代表原图片被删除。
- 不把模拟浏览器的通过声明为物理iPhone键盘、PWA或长期使用效果。本轮不发布、push或重启两机服务。

## 后续优化候选

`submittedQueries.ts`的会话内store保留已完整回显/已dismiss的正文，长时间使用会增长；合成300个16k字符已回显Query仍保留约9.6MB的UTF-16正文估算，不是实测堆占用。后续可在不保留正文的轻量终态记录与历史缓存之间划清职责，再对已完成记录做有界回收。

本轮暂缓：这些记录同时保护迟到队列快照、请求身份和附件显示，直接删除可能复活旧行或丢失展示内容。重开条件是要处理长期内存占用，或有实际内存压力证据；最小验证应覆盖已完成正文释放、旧快照不复活、unknown/进行中POST/待发正文不被裁剪、跨会话返回后的精确身份交接。
