# 最新对话的消息来源与阅读连续性

2026-11-11。欧吉安明确反馈「飞象工作台」在**最新一轮**向下滑动时回跳，无法顺利读到末尾。此前[历史滚动接管](2026-11-11-history-scroll-takeover.md)修复的是另一条通知与 React commit 竞态；不能将它当成本次最新消息问题已经解决的证据。

## 证据与边界

只读目标会话的结构：保存来源19条、桌面来源77条；3个重复ID的文字、角色和轮次一致，最新final同ID但正文长度322／682且非前缀关系。结构记录没有完整证明时间戳、附件等所有展示字段均相等，因此不承诺真实77条一定被精确去重成74条。没有输出正文、打开owner、发送Query或调用飞象业务服务。

双浏览器结构模拟确认：桌面与保存来源反复切换，旧React key会留下额外DOM消息；成功的短rollout回退与HTTP失败不同，前者会缩短正文，WebKit可能将读者夹到末尾并误跟随。旧版永久浏览器回归14项中12项失败，包括重复行增长、前缀消失及关闭原生CSS锚定后的保存来源单独更新，上方扩展让末尾偏移从-510变1602。两项迟到native前缀检查在旧版已通过，不能算新增修复。

## 实现

- `displayMessageIdentity.ts`只合并相同非空ID、完整展示字段相等的记录，保留原对象与顺序；冲突记录原ID不变，使用独立React key。过程分组冲突也有独立披露ID。
- `readableConversationContinuity.ts`只保留最后一次桌面阅读投影的安全旧前缀。共享ID／角色／非空轮次／顺序确定边界，最新尾段使用本次fresh对象；分支或身份不明就不拼接。替换用户ID时按轮次边界截去旧Query，保留前缀最多与fresh合计80条／160k字符，优先淘汰旧前缀。
- 旧前缀限当前电脑、来源scope与会话的详情内存，不写入读取缓存或原历史。fresh history仍决定连接、运行三点、停止、发送和回执；提交消息观察使用原`liveDisplay.messages`。
- `liveReadingAnchor.ts`在两路feed通知前记录唯一可见消息及偏移，DOM提交前若又发生滑动便重新捕获。新布局恢复共享可见消息的位置，不回放旧scrollTop；没有安全共享消息就不写位置。历史窗口、底部跟随、选区／控件焦点／阅读动效各保留其归属，不抢夺操作。
- 冲突ID不能被ID索引的timeline或提问卡吞掉：两条来源正文都保持可读，尚待处理的本地Query与新题另有正常入口；不唯一的阅读标记或滚动锚点不被采用。
