# 会话信息的稳定布局与短期缓存

2026-10-31。用户发现会话信息弹窗打开后先高后低，并询问是否应缓存信息。

## 根因与改动

- 定时任务首读为标题、读取提示两行；确认空结果后才切到单行布局。旧发布包在 Chromium/WebKit、390/1280px 四组实测均缩短约 25.4–25.5px。
- 将读取、刷新和空结果提示都放在定时任务标题右侧。后台刷新保留已有计划，不插入额外 loading 行；真实错误保留解释和重试入口，未知状态不冒充没有计划。
- 标题、工作目录、项目、创建时间等继续来自已有目录数据。定时任务详情和模型摘要增加页面内短期缓存，连续打开不再从空态开始。

## 缓存契约

- `src/threadInfoCache.ts`：按电脑、来源 host、thread ID、信息类型隔离；30 秒内直接复用，之后先展示旧内容并在打开时重新读取。最长保留 5 分钟，最多 64 项、约 1MiB；按最近访问淘汰，读取不延长新鲜期。不写入磁盘或 Service Worker。
- 定时任务只缓存已成功确认的只读信息，包括确认没有计划。目录中的计划数量/启停摘要变化会提前重读；刷新失败保留已知内容，并明确状态尚未确认。
- 模型只缓存当前型号、思考强度与显示名称；`revision`、修改权限、可选强度和操作回执不进入缓存。点击修改仍读取最新设置，未决操作仍走原 requestId 核对；成功回执能更新纯显示摘要。
- API 的认证及来源清理同时撤销信息缓存。请求持有缓存代次，退出、来源变化或失效后到达的结果不能重新填回旧数据；不同电脑和会话互不借用。
- 缓存用于展示与降低重复读取，不触发 Mac 打开会话，也不改变发送、归档、已读或定时任务调度。
