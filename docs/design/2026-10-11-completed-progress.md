# 最终回复后的过程折叠

## 呈现规则

- 在已展示消息中，找到同一明确 turn ID 的首个有效 final/final_answer。只有它之前的 assistant/commentary 具备折叠资格；无轮次、无 phase、空或只有隐藏标记的最终消息不作为依据，idle 状态也不等于有最终回复。
- 连续的同轮过程成为“查看过程 · N 条”，点击可展开全部已加载原文。用户消息、最终回复、问题和其他轮次打断分组，保持原顺序。最终回复之后的新过程继续显示。
- 正在上翻、选中文字或操作正文内控件时，新获得资格的过程段暂时保留；回到最新且没有选区/正文交互后再折叠。当前已完成历史首次打开默认折叠。
- 手动展开状态、暂缓折叠记录随本次登录内的原有10条历史缓存保存；轮询、切换会话不重置，缓存淘汰或页面重载后恢复默认。不在localStorage保存正文。
- 当前问题及其附加说明不进入隐藏区；提问、审批、发送和已读语义保持。

## 连续性与边界

`groupProgressMessages`只生成展示结构，保留原消息对象。`shownMessages`仍完整供消息核对、问题匹配和已读凭据验证；折叠不删除历史、不核销发送，也不改变服务端数据。

原生与保存记录有时在final先到时替换整轮消息ID。选区存在且其节点将被替换时，保留上一份呈现直到取消选择；完整的新消息仍参与底层核对。正文选区同时阻止自动跟随底部。手动展开/收起以触发按钮的位置为锚点，避免把正在看的过程推走。

布局调整后再恢复已读观察，选字期间不提供标读凭据。末尾最终回复或问题继续位于折叠区域外，必须实际显示在阅读区域内才可按原契约标读。

折叠数量只表示当前已加载的过程条目，不扩大原有历史读取范围。无法确认轮次的旧消息继续展开。
