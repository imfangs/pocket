# 结构化消息的统一安全展示

2026-11-05。定时检查的一个最终回复包含完整 heartbeat、随后追加的音频 Markdown、details 折叠区和引用尾段。以前要求整条消息必须完全匹配包装，导致正常续文让整条回复退回 XML 代码框。多次逐格式补尾段也容易遗漏用户角色、子任务或跨段引用。

## 统一入口

`messageEnvelope.ts` 的 `projectStructuredMessage` 只处理两个静态注册的已知包装。共同负责前缀/大小/代码示例保护、闭合候选、合法续文、外部引用与惰性回退；heartbeat 字段和 subagent JSON 各自保留严格 schema。旧文件成为小型展示适配，不再各自判断尾文种类。

| 输入 | 展示规则 |
| --- | --- |
| heartbeat 触发/结果 | 身份字段必需，重复/未知字段拒绝；decision 不触发动作；instructions 与 message 不混用 |
| subagent_notification | 严格 JSON、唯一键、已知状态；agent_path 不作为文件路径或导航权限 |
| 完整已知包装＋普通 Markdown/代码/媒体/details 续文 | body 与 continuation 分开投影，正常续文保持排版；不由是否包含媒体决定合法性 |
| 外部 raw/encoded/截断 citation | 只在续文自身的 Markdown 范围内移除；正文和代码例子不预清理 |
| 未知、重复、缺失、未闭合包装 | 可读的惰性代码回退，不能执行或变成交互表单 |
| 普通消息的原始 HTML | 保留既有 skipHtml；隐藏 HTML 里的 Codex 组件不会升级为可见组件或权限 |
| 未支持 XML/已知包装字段里的 HTML | 惰性可读内容；没有 raw HTML、XML 引擎、实体外联或 eval |

闭合字段不能吞掉重复字段，代码/链接中的字面闭合标签仍是字段正文。帧起始处四空格、tab、围栏与行内示例不进入包装解析。原 message role/id/text、回执、版本、read marker 和权限始终留在原链路。

## 安全折叠区与引用

`messageDetails.ts` 只识别闭合的 details/summary 形状及可选 open，拒绝其他属性；标题按文本渲染，正文继续使用安全 Markdown。未闭合、孤立关闭、未知属性、超限和深度限制均保留为惰性内容。特殊标签与标题被等长遮蔽后，仍由现有 Markdown 解析器识别正文的代码/链接范围，避免把代码里的 details 当成折叠边界。

拆分正文与折叠区共用整条展示投影的第一定义表。定义在区块前后仍可解析，重复定义不覆盖首条；隐藏引用不能贡献定义。原生折叠节点在普通流式续文中保持身份和手动展开状态，交互告知已有阅读可见性控制，不改滚动/输入/选择的控制权。

## 媒体与权限

音频图片语法按文件引用展示，已经登记的引用沿用既有文件入口；没有授权时显示标题与「文件保存在电脑上」。普通本地图片缺少登记时也给同一轻量提示。没有新增音频播放器、读取路由、CSP 权限、文件授权或目录放宽，仍不自动请求外部媒体。

子任务内部正文继续不继承 files/images；普通外部续文只消费原服务已经提供、绑定当前会话的映射。实际反馈中的两个文件均未登记；测试确认零 audio/img/video 元素和零媒体读取。
