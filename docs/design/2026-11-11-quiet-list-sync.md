# 弱网同步收成细线

2026-11-11。欧吉安截图指出筛选下方“状态尚未同步，显示上次同步的列表状态＋重试”反复出现，占用阅读空间，希望短暂弱网用动态细线，明确断网才给文字提示。截图与源码确认原提示最少44px，数据状态变化会把已有行推下；未展开截图内的会话内容。

## 展示契约

已有目录始终保留2px反馈槽，正常空闲透明。目录／列表状态实际请求中才移动银灰线；短暂失败、原生`available:false`、TTL过期、部分unknown和缓存回退只显示静态淡线。等待同步与完成读取不同，不用细线伪造百分比、恢复权限或确认消息发送。普通同步描述留给辅助阅读，不用live区域每次播报；稀有警告保留状态语义及44px重试点击区。

浏览器明确`navigator.onLine=false`立即显示简短离线提示。其它连接问题需单条读取链路至少3次失败且持续30秒，并且没有另一条列表读取在这段失败之后证明可达，才显示“连接暂未恢复”。因此目录仍成功时，状态源不可读不能被宣称成整机断网。重试中不清失败链，真实成功才清除；后台／离线取消、scope更换重置展示诊断，前台重新给予恢复机会。HTTP5xx是服务链路不可用的宽泛证据，文案没有断言互联网物理断开。

无缓存的首屏仍有原来的加载／失败恢复入口。现有运行缓存、排序、数量和详情控制权限保持，通知跳转与输入保护不依赖新线条状态。

## 实现与验证

`readHealth`／`useReadHealth`仅管理读取展示诊断；目录reader和状态polling分别报告开始／可达／失败／结束，不能把native unavailable当网络失败。CollectionReadFeedback分开实际请求、等待与真正警告，不使用包含上传／回执的全局NetworkTitle请求计数冒充列表同步。

候选build`f06716b2d582f35a3a89ee797340352cfa9629e31ad1c5906b263c31ee8a3893`：40项同版浏览器（12新状态、8原列表活动、20通知）及56发送／追加／来源宽回归通过，完整2286项全绿。旧版短暂失败让列表下移44px；修复固定2px，已确认旧节点、阅读位置、排序和计数保持。正常／减少动效、英文320px、离线／恢复以及3次失败后29999ms无警告→30000ms警告都有实际浏览器链路验证。

独立CR发现被隐藏取消的旧请求仍可能迟到记录超时，已加入ready／signal／owner检查并清除挂起deadline，实际ignored-abort负例通过。首轮两项浏览器30秒边界失败来自未暂停的虚拟时钟自行前进，失败日志保留；暂停时钟后整轮通过，没有修改产品阈值迎合测试。原反馈SSR与通知／活动测试只更新展示约定，其读取／状态／输入断言保持。
