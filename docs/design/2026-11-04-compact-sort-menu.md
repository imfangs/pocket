# 标题栏排序菜单

2026-11-04。用户指出英文创建/活动排序换行占用固定阅读空间，认可把它们收进标题栏的单个排序按钮，中英文统一。

## 当前交互

- 标题栏加号左侧是44px排序按钮，沿用线性排序图标与透明控件。当前模式写入无障碍名称和提示，非默认模式轻量强调；菜单明确勾选当前项。
- 三项为智能排序、创建时间、活动时间。创建与活动仍从新到旧；活动采用最后消息时间。智能排序的原rank公式，以及隐藏/归档集合的时间回退都保持。
- 创建/活动两个常驻按钮移除，未读、运行中、关注与搜索保留一行。英文最小屏仅压缩装饰点与内侧间距，完整名称、数字、字号、选中表面和44px点击区保持。
- 用项目已有Radix Themes DropdownMenu单选菜单，复用键盘、触屏、焦点、关闭、定位与主题能力。非模态打开避免锁住页面滚动；使用标准勾选占位和文本，没有叠加另一套状态图标。
- 选择当前项是无操作，不重置滚动或重新读取；切换模式只调整排序及列表位置，保留分类、项目、活动筛选、搜索、桌面当前会话、草稿和原消息节点。选择在该电脑的既有导航偏好中记忆。
- 新`setSort`是显式选择；旧`sort`切换契约仍保留。没有新的存储格式、后端写入、连接、发送或原Codex控制。

## 实测效果

中英320px、英文390/768px的标题区由181/197px减少到125/141px，恢复56px阅读空间；原单行的中文390/768/1280和英文1280再少6px。筛选区均为44px。320px英文未读128/运行32及双选中样式也能单行，文字和计数完整。

桌面选择相同和不同排序都保留输入、消息节点、草稿与选区。菜单的选中、亮暗、鼠标/键盘高亮经实际样式合成，最小文字对比5.206:1。关闭菜单归还排序按钮焦点；外部新建弹窗已接管焦点时不抢回。

## 验证与修复过程

独立复核发现并修复两处原导航副作用：RadioItem重选仍可能触发回调，仅reducer幂等不够；原`updateNavigation`会关闭桌面详情，新显式排序保留它。英文128/32组合在选中加粗后有不到1px的换行边界，已补选中状态检查并调整间距。

最初Chromium键盘用例在异步roving焦点移动前立即读取，WebKit则因调用延迟通过。改为等待实际菜单焦点及End移动完成，同一实现复验通过。另一个独立报告把仅布局数据中的缺失键盘字段当作false，原报告和审计保留，补最终键盘数据后正确分层汇总。

常规验证从`tests/browser/sort-menu.test.mjs`和`tests/navigation-dimensions.test.mjs`进入，旧英文布局回归已同步到单行要求。证据在`.local/qa/sort-menu-2026-11-04/`，准确全测/最终包、发布与余下边界回[CURRENT](../../CURRENT.md)。预算限制下仅使用真实浏览器DOM、文字范围、焦点、命中与颜色合成；没有目视/真机或真实会话写入。旧私有截图与构建仅作当时证据，不当成当前版本。
