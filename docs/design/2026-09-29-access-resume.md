# 前台恢复时的登录状态顺序

2026-09-29。持续打磨的本轮范围：启动/切回前台触发多次认证检查时，避免较早的响应覆盖后续登录、退出或明确过期状态。

## 已复现

使用隔离服务和 390×844 Chromium 触控上下文：暂停第一次 `/api/auth/status`；派发前台事件，让第二次检查先返回未登录；完成真实口令登录，打开合成任务并输入草稿；最后释放第一次的未登录响应。

修复前页面退回登录框，App 卸载，内存草稿丢失。不是断网导致服务端注销，而是旧认证观察晚到并覆盖了更新的状态。初次脚本等待时间过长，旧请求已自行超时，没有复现；改为在请求发起后立即推进后续步骤，稳定取得原缺陷。证据 `.local/qa/auth-resume/baseline.json`。

## 修复

`accessCheck.ts` 管理只读状态检查的代次：仅最新一代能回写。登录和退出开始时暂停检查并让已有观察失效，操作结束后恢复；明确认证过期也让此前检查失效，组件清理后不接受迟到结果。

保持既有认证、七天会话、CSRF、网络错误时保留已登录页面的行为。没有持久化草稿、隐藏真实会话过期或自动重发登录/任务请求。真实过期仍进入登录页；该修复只保护不应发生的旧响应回退。
