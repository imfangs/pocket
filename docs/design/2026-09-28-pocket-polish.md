# Pocket 视觉打磨 · 2026-09-28

用户授权按判断优化现有界面。保持轻量随身工具的密度和原信息架构，集中改善任务列表、会话、输入和操作卡片。

## 视觉系统

- 白底与中性灰文字，少量紫色 `#6254c7` 表示选中、链接和 Codex 回复身份；绿色仅提示正在执行，红色用于停止，黄色保留给审批。
- 系统字体和 PingFang SC：手机任务标题 15px、会话正文 15px / 1.85、所有编辑文本至少 16px。标题、辅助文字与控件分级，减少低对比绿色小字。
- 列表保持连续行、细分隔线；移动端批量勾选按需进入“选择”，保留全选/加入分组/稍后功能。
- 用户消息：淡紫气泡；过程：灰色左侧细线；最终回复：开放正文、紫色身份标签。阶段与文本解析不变。
- 输入框和发送按钮合成一个圆角容器，焦点提供轻微边框反馈；原自适应高度、首次键盘和回答编辑布局规则保留。
- 表格细线、代码块统一头部；代码和回复提供复制。远程图片继续只显示链接、原始 HTML 不执行。
- 动效限于 140–180ms 的颜色、阴影和弹层进入；尊重减少动态效果设置。详情页祖先不增加 transform。

## 组件取舍

引入 `@radix-ui/react-popover` 管理上下文浮层的碰撞避让、Escape、外部点击和焦点返回；引入 Sonner 提供根级、可划走的短反馈。错误与未知发送回执仍留在原业务界面。应用主体延迟到登录后加载，构建分为两个约 277KB 的 JS 模块（gzip 合计约 176KB）。

本轮不整包引入 AI Elements / Tailwind，也不添加 Motion。前序注册表研究确认现有 Markdown 和队列逻辑已经具备所需能力，MessageResponse 的额外插件与渲染迁移不能直接解决本次排版问题。CSS 足以实现本轮动效；避免用依赖数量代替交互质量。

`styles.css` / `pwa.css` 保留功能布局，统一旧色值；`polish.css` 集中维护视觉层和响应式视觉变体，后续不要向各功能文件散落相似覆盖。新行为由 CopyButton、MarkdownCode 和 ContextStatus 明确拥有。

## 视觉核验与有意偏差

内置浏览器真实渲染，390×844、320×740、1280×900；截图本地生成受控预览后看图。无可用内置 Image Gen，因此本轮使用原页面基线与新版渲染对照，没有生成或宣称获得用户批准的概念图。原始截图和回执仅放 `.local/qa/`，不含真实用户会话。

| 对照点 | 基线问题 | 最终处理 |
| --- | --- | --- |
| 色彩 | 全局偏绿且辅助文字过淡 | 中性灰白、单一紫色强调、语义状态保留 |
| 消息容器 | 回复卡片、左边框、内部表格重复套框 | 开放正文，仅用户消息保留气泡 |
| 字体 | 标题与辅助文字过小、层级不清 | 分别校验标题、正文、过程、输入与工具栏字号 |
| 输入 | 输入框与发送按钮视觉割裂 | 单一容器，焦点边框、随内容增长 |
| 列表 | 每行常驻复选框抢占空间 | 手机选择模式；桌面批量入口保留 |
| 图标 | 顶部以关闭图标表达返回 | 手机左侧返回箭头，桌面保留关闭 |
| 浮层 | 上下文原生 details 无外部关闭 | Radix 弹层，窄屏不超出边缘，Escape 返回焦点 |

可见文案有意改动：删除桌面列表副说明和空状态重复提示；刷新成功缩短为“任务已刷新”；增加“选择/完成”和复制控件的无障碍名称。既有停止、队列、回答、压缩和审批语义保持。无新增营销说明、统计指标或无效功能入口。
