# Pocket 与桌面会话列表范围

2026-10-14。用户发现手机列表出现后台批量选题任务，和 Codex 的置顶、项目会话不一致。

## 原因与范围

只读检查确认，报告的六条任务在源库中仍为未归档，来源为 `exec`，不在 Desktop `local_thread_catalog`。旧 Pocket 来源适配把独立执行记录也纳入列表；这不是原归档操作失败，也不能靠标题关键词判断。

当前 App 26.1007.30912 / 20156 的目录构造逻辑明确排除 exec、隐藏内部来源和子节点。Pocket 保留现有 `vscode/cli/app` 来源，增加这些来源与父子关系约束。`thread_spawn_edges` 不存在时兼容旧库；存在但结构无效时整次读取失败，保留上次成功快照。

不以桌面目录成员身份作为准入条件。它是异步投影，新建与归档历史具有不同的同步时序。新建普通任务可直接进入 Pocket；原归档任务继续只在归档视图出现。后续桌面协议变化时应复核来源规则，不把本轮具体 App 版本当连接准入门槛。

## 同步与输入保护

- 来源返回正向会话、明确排除 ID 和排除对象的真实归档状态，三者在同一源库读取事务内生成。排除对象不再读取正文。
- 旧缓存保留为 `sourceExcluded`，原 `archived`、缺失、注释、置顶、队列和回执独立处理。排除不是删除或归档。非法排除集合/状态原子拒绝，来源失败保留旧结果。
- catalog、搜索、项目未归属入口、待输入/运行计数和 Rank 共同排除；迟到状态与生命周期元数据不能复活行。
- 正在阅读的详情继续保留并同步真实归档状态。有草稿、附件或未完成发送内容时，离开详情后可通过临时“保留的输入”入口找回；它不参与普通会话列表和计数。处理完内容后移除入口，不增加常驻导航功能。
- 正向来源再次纳入时清除排除标记，恢复原注释与 Pocket 置顶。
