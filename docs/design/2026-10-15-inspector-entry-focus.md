# 详情与弹窗的焦点

2026-10-15。方帅反馈触摸进入会话后，返回按钮偶尔带蓝色圈，像被选中。它实际是程序把焦点移到返回按钮后触发的focus-visible样式，不是选中状态。

入口增加与动画独立的pointer / keyboard / programmatic语义。真实点击的detail区分指针与键盘/辅助技术激活；移动端键盘进入聚焦返回按钮，指针、通知、深链和新建完成聚焦非交互详情容器。仅该容器取消outline，所有按钮的键盘轮廓保留。焦点使用preventScroll，在导航动画绑定前设置，避免focusin误取消转场。

图片和信息弹窗关闭仍恢复各自触发器，不重跑详情入口逻辑；新建弹窗退出后的补焦点采用同样的容器策略。桌面行为保持，未改归档、发送和图片接口。

39项定向回归和最终构建的两引擎25项完整App检查通过：真实touch后的返回按钮不active、不focus-visible；Enter进入后的返回按钮active且focus-visible，Tab轮廓保留。覆盖聚焦搜索再触摸、键盘再触摸、鼠标、减少动态效果、通知/深链、新建完成以及图片/信息弹窗返回。短视口和自动浏览器不能代替真实手机辅助技术验收。

## 2026-11-03 返回列表的竖线与弹窗默认焦点

用户截图IMG_8875中，右滑返回后第一行左右出现贯穿行高的浅紫竖线；随后反馈关闭按钮经常像被选中。旧包`8a5b74f8…`的独立浏览器复现显示：输入后右滑会把焦点程序性移回`task-select`，2px/offset 3px的focus-visible轮廓上、下边被`overflow:hidden`裁掉，仅留下左右两边。保留草稿/清空后均可复现；正常绿色运行状态线无关。

- 关闭来源独立于动画：手势和点击返回属于pointer，键盘/辅助技术激活属于keyboard，不能用“无动画”推断键盘。
- pointer/programmatic返回聚焦中性列表容器，keyboard返回原会话按钮。新选择、scope变化、新输入/焦点、弹窗和inert导航会阻止迟到恢复；新选择/卸载abort，回调结束清理监听。
- 共用Modal以可用的`data-autofocus`为优先，其他情况落到静态标题。新建输入和重命名异步就绪聚焦保持；未给原生dialog加tabindex。
- 移动菜单默认聚焦导航容器，首次Tab/ShiftTab进入首/尾控件。图片预览聚焦阅读区域，文件预览聚焦文件标题；真实按钮的focus-visible、Escape、缩放、下载和嵌套归还继续保留。
