# 阅读态输入区与列表状态位置

2026-10-13。范围是 Pocket 的手机阅读、输入和列表扫描；实现与当前发布身份见 [CURRENT](../../CURRENT.md)。

## 来源、基线与取舍

参考 [Hermex UI 研究](../../../research/hermex-for-us-2026-10-13.md)的两项机制：输入区随焦点和操作展开，列表状态与时间共用尾部位置。研究对应源码 `c9efaa97d6f020df8bb8b4c91c1b36648fe72f33`，宣传图和源码支持机制分析；本轮未运行 Hermex，未验证其原生手感。不复制管理首页、品牌、模型设置或后端。

Pocket 改前代码为 `bb2bd415de0a4f7088efc97cca9096d6fdb02367`，前端 build 为 `c3fb675c20d149e6075c61faf69ce00b99af5ec76c28e4a2e8159d0a09ba07a7`。对照使用同一合成列表、同一篇长回复、390×844 视口和相同阅读段落，分别检查浅色与深色。旧构建独立保存用于对照，真实任务数据未进入素材。

## 输入区

仅在窄屏、无悬停的粗指针设备上启用。已有正文、空草稿且没有附件、待处理操作或反馈时，输入区收为一行；点击输入展开。新建空会话与鼠标桌面保留完整输入。紧凑态保留可编辑文本框与附件入口，隐藏此时本已禁用的发送按钮。

文本框始终是同一个 DOM 节点，收放只改变布局和行数。非空草稿（含空白字符）、附件/上传错误、提交与未知回执、待发、待回应问题、操作反馈、焦点、组合输入、文件选择或已确认键盘打开时保持展开。没有闲置倒计时，也不为收起而主动 blur/refocus、清稿或重建输入。

文件选择使用独立的操作保持状态：change/cancel 释放，窗口回到前台有短暂兜底以等待文件事件。实际浏览器复现了一个首次实现的问题：按下附件按钮时聚焦引发输入区展开，按钮在 pointerup 前移位，导致点击落空。修复仅对本输入区的附件按钮阻止指针抢焦点；click 中设置 picking 并同步调用文件输入，React 随后批量更新布局。Tab/Enter/Space 不拦截。不能把事件模拟当作 iPhone 系统选择器验证。

高度变化继续复用既有滚动规则：本来跟随底部且未选择/操作正文时才跟随；上翻时保留位置。顶部运行工具栏本来就在正文滚动区外，始终可见，因此没有给“返回最新消息”再加一条常驻状态。

## 列表

等待确认、等待回答、运行中占首行右侧同一固定宽度位置，并取代该位置的相对时间。空闲恢复时间，第二行不重复显示这三种状态；项目、草稿、置顶、未读和状态待确认等仍按原规则显示。不可用提示保留，未把 unknown 当成 idle。

修改仅派生展示位置：原状态优先级、有效期、候选覆盖、排序、原任务身份、左划置顶与执行语义保持。状态槽沿用原主题颜色与运行绿点，取消额外底色块，不新增入口。

## 验证与限制

- 712 项全量回归、TypeScript 与生产构建通过；定向状态测试覆盖输入保护与列表状态语义。
- 合成浏览器 33 项检查通过，覆盖浅/深色、320/390px、760px 鼠标窄窗口与1280px桌面；有正文的空稿阅读、聚焦、编辑、合成键盘关闭/IME、上翻、附件、返回、运行、待发和待确认。
- 390px 对照中，输入区 **118→54px**，正文高度 **600→664px**；同一段落顶部 `124.125px`、scrollTop `736` 均保持。多出的64px是布局测量，不等于已经测得阅读效率或主观舒适度提升。
- 附件打开通过实际浏览器 filechooser 事件核验；点击位移缺陷有修复前后事件轨迹。额外触控和键盘入口结果保存在同目录。
- 所有操作使用合成对象，未向真人会话发送 QA 消息。iPhone 主屏幕、真实中文输入法及系统文件选择/键盘动画仍需实机使用反馈。
