# Pocket 阅读状态与桌面已读合并

2026-10-22。方帅在[未读对照研究](../research/2026-10-22-unread-comparison.md)之后确认：由 Pocket 维护自己的会话阅读状态，不再强求与 Codex Desktop 蓝点一致。随后欧吉安反馈双端重复未读，并授权默认合并桌面已读；当前规则如下。本文件取代旧[原生已读同步](2026-10-05-read-state-sync.md)作为当前产品契约；旧文保留历史实验与未解决的上游故障。

## 用户行为

- 进入会话，最新完整回复末尾真正出现在前台、无遮挡的阅读区域后，立即清除 Pocket 未读。返回列表和刷新后保持。
- 新鲜桌面状态确认对应内容不再未读后，Pocket 合入其已读水位，无需逐条重新打开。不增加开关；Pocket 读过的版本不会被桌面旧未读反向覆盖。
- 新回复或同一条回复新增内容时重新变为未读；在旧滚动位置、后台或浮层下收到内容不视为已读。
- 列表标记、未读筛选、数量与智能排序使用同一判定。有效运行中只显示运行状态，不计入未读；新内容与实际阅读仍正常记录，结束后按阅读水位判断。已读的等待回答/审批继续显示待处理。
- 不再提供“同步已读”重试或同步失败提示。新界面不调用原生标读接口，也不为阅读重启或连接 Codex。

## 内容版本与阅读水位

服务端复用现有历史解析和有界文件尾缓存，为最后一条可读 assistant 消息计算完整内容摘要。身份、正文和 phase 参与摘要；推断出的 turnId、设置变化、Token 事件和打开时间不参与。隐藏分析、注入上下文与压缩摘要沿用原过滤。只有用户消息时不会产生一条新 assistant 未读。

`pocket_content` 在 Pocket 自己的 SQLite 中保存每会话的递增 revision、摘要、目标消息 ID 与当前可知性，不保存正文或用户已读。相同内容不增加 revision。读取和登记同步进行，源文件指纹和进程内观察顺序拒绝旧快照。目录和 transcript 共用同一份版本账本，不重新扫描第二份完整历史。

API 提供 `pocketContent = { scope, revision, version, messageId, known: true }`；未知返回 `known: false`，已知空会话的 `messageId` 为 null。只有完整目标确实包含在 transcript 中，才提供可用于阅读确认的内容版本。正文截断不能被当成读完。

浏览器按 **电脑 + 来源 scope + thread ID** 保存最新已知版本与已读版本。scope 存在 Pocket 设置中，普通服务重启保持；换新数据目录/来源建立新 scope。恢复旧 Pocket 数据库需要同时更新 scope，不能承诺回滚数据库后仍自动保持 revision 单调。

首次看到某会话时按原生未读建立一次基线，原生明确 false 优先；没有原生状态的旧内容以当前版本为基线，避免全部历史突然变蓝。之后原始 native true/false 都不能直接覆盖 Pocket 的阅读判断；只有下节的精确版本 `desktopReadContent` 能单向推进已读。更高 revision 的新内容产生未读，迟到目录/操作/阅读结果不能回退水位；同一 revision 的不同摘要视为冲突，不能悄悄标读。

同源多个标签按会话单独合并 localStorage 更新，避免整表互相覆盖。每机最多保留 4096 条阅读记录，按实际阅读/内容变化保留近期项；普通目录轮询不制造访问。达到上限后移除旧水位，再次出现的缺失旧记录按当前内容建立基线，不重复导入 Codex 蓝点。存储不可用时退回当前页面内存，不阻断阅读和发送。

## 桌面已读合并（2026-10-22 后续修正）

首版完全独立的水位使“已在 Codex 看过的回复”仍在 Pocket 未读。本轮保留客户端水位，把服务端提供的 `desktopReadContent` 合入 seen；有效已读为本地阅读与桌面提示的较高版本。相同 revision 的摘要/消息身份冲突仍不可确认；提示不得超出携带它的目录内容版本，也不能跨电脑或来源 scope。

桌面目前只有会话级未读集合，没有逐消息阅读时间或水位。因此 `desktopReadContent` 表示“Codex 在这一内容版本的稳定采集中没有未读标记”，不是严格的跨端逐消息阅读证明。

- 来源扫描前后都验证当前 API-key/local identity/host 的 v1 数组确实存在、有效，且不包含该会话。缺字段、legacy、未知或读取失败不生成提示；旧首次基线兼容保持。
- 当前轮已结束从同一次有界历史尾部采集得到；读取中变化、正在运行或未知不能开始确认。内容仍通过文件指纹与观察序号核验。
- 对相同内容与源文件版本取得至少两次新鲜观察，间隔至少 2 秒，才生成提示。新版本、重新运行、原生未读或未知会撤销候选；重启后重新建立。它降低 rollout 先落盘、原生蓝点后更新的竞态，但不承诺任意延迟下零误差。
- 客户端同步有新候选时最多等待一次 2 秒的复核，同一批并发同步共用请求；没有候选则保持立即返回。既有 45 秒后台采集保持，不新增桌面连接或高频全量轮询。
- 提示只在新鲜 source 采集中生成，保存时带固定 scope/revision/version/messageId。普通 catalog 可以返回旧提示，但绝不用较新的内容账本给旧提示重打版本；正文先更新时，旧提示无法清掉新内容。
- 浏览器渲染、计数、筛选与排序共用同一合并函数，收到提示便持久化推进水位；未知/离线保留已读，原生旧 true 不能反弹。已有 v1 阅读记录原地兼容，不清本地存储。

原生写回仍未恢复，本轮不调用 setter，不重启 Codex。等待回答/审批、运行、发送及待发回执继续保持独立。只读真实源、合成竞态和双浏览器验收结果回 CURRENT；iPhone 长期跨端体验仍需真实使用反馈。

## 阅读观察

观察点放在目标 assistant 消息或对应问题卡末尾，不能放在后续用户消息之后。两帧检查可见性、几何、页面前台、遮挡与实际展示内容。最新阅读目标保持展开，新的最终回复出现后旧过程仍可折叠。

缓存和离线允许标记实际看见的那一版本；不得借此确认尚未显示的新版本。原生正文领先、ID/正文/phase 冲突、截断或未落到正文的新问题都不能确认阅读。历史尾部缺少轮次上下文不等同于不同回复，不能仅因未知 turnId 阻断完整相同内容。

## 状态与数据边界

- 发送、排队、停止、审批、压缩、归档等继续使用原 owner 与既有请求回执。阅读水位不授予执行能力，不核销未知发送。
- 原生已读接口仅保留旧客户端兼容，不被新界面调用。此版本不承诺 Codex 蓝点同步或两个手机之间同步已读。
- 浏览器持久化的只有摘要/ID/版本，不是聊天正文。既有 10 会话内存历史缓存、草稿保护和 Service Worker 仅缓存公开壳的策略保持。
- 清除浏览器站点数据或重装 PWA 会失去这些阅读记录。没有来源正文的会话不能凭旧蓝点猜测内容版本，已有本地记录在暂时未知时保留。

## 2026-10-26：运行中与未读的列表呈现

来源：欧吉安在已读合并上线后询问“运行中的是不是不能归类为未读”。10-23交接曾明确记录尚未实现；10-26再次指出后补齐。历史缺口是 `pocketUnread` 的提前返回绕过了旧API已有的运行中排除，旧回归还明确断言两类计数均为1。此前建议不能作为上线证据。

当前实现：`hasUnreadContent` 在读取 `pocketUnread` 或旧API兼容标记前先排除有效 `running`。`threadListStates`、`navigationActivityCounts`、`filterThreads` 共用它，列表徽标、数量和筛选一起变化；智能排序原本已经排除运行中的未读加分，本轮权重不变。

- 运行中未读水位保留；结束后尚未读到的内容回到未读。运行期间实际读过的版本结束后保持已读；同条回复继续追加的新版本仍按实际阅读判断。
- 等待回答/审批继续独立显示；未读可与等待操作并列，读过不会替用户回答或批准。
- 过期、断网、加载中或未知不等于已完成：沿用运行状态有效期，撤下失效运行标记，保留已有内容和水位，已知未读仍可显示。恢复后收到有效运行状态，再统一排除。没有新增持久运行缓存，也不把缺失状态写为 `idle`。
- 不因运行中调用 `markSeen`、推进水位或修改 Codex 状态；旧桌面已读提示和旧正文观察仍不能清掉更高版本。

验证：先修改契约回归，在原实现稳定复现3处失败，再调整共享判断。新增运行→结束、运行期间阅读、同条追加、旧桌面提示、未知状态及真实 TaskList 渲染检查；83项定向、1377项完整回归与60项双浏览器通过。原有跨标签测试会因时钟跨毫秒偶发多一次元数据合并通知，本轮固定其时钟并补异时钟回归，未改产品存储。10-26已发布：源码 `7f9b7ebd48f2bfcc27c1e8222f4a88436ab9ae17`，Pages `b9137fa4-09b7-4d5f-80aa-77f379bf53e1`，30/30公网文件及功能检查通过。仅更新网页，未重启Mac服务或Codex。完整回读见 [CURRENT](../../CURRENT.md) 和 `.local/qa/running-unread-2026-10-26/`；这些检查不代替物理iPhone长期使用证据。
