# 长 Query 的阅读收敛

2026-10-14，方帅反馈已发送的 Query 太长会占据大量屏幕，希望超过一定长度可以展开更多。

## 当前呈现

- 只处理已发送的用户消息。按当前宽度下正文的实际高度判断，超过约 6 行正文高度时收起，下方显示“展开更多 / 收起”；短消息不增加控件。
- 高度包含 Markdown 段落、标题、列表等排版间距，不以字符数猜行数。保留原 Markdown 节点，改变宽度或文字时重新测量；没有高度动画。
- 图片附件、文件附件、时间、发送确认和整条消息复制始终留在外面。含已注册内联图片的正文保持展开，避免把图片高度当成长文字。输入框、待发队列和 Codex 回复保持现有呈现。
- 复制仍使用完整的可读原文。视觉裁切不删除或截断正文，辅助阅读仍可读取全文；被裁掉的交互控件不进入 Tab 路径，预览内完整可见的链接可直接使用。表格/代码滚动容器只移除自身 Tab 入口，不连带禁用可见子链接。

## 连续性

展开保留正文顶部位置，收起保留底部按钮位置。两者复用过程折叠的布局保护：先暂缓贴底和标读，布局后恢复滚动，再恢复可见阅读观察，避免点击展开后被送到全文末尾。

手动展开状态随本次登录内原有 10 条会话历史缓存保存，历史和正文轮询都保留；离开再返回不重置。标识优先用发送 request/clientMessageId，其余使用原 message ID；不按相似文字合并不同消息。缓存淘汰、重新载入页面后恢复默认，不把正文写入 localStorage。
