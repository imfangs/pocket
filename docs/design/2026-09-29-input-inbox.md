# 待我输入：与任务列表共存

2026-09-29。用户目标是快速找到需要人接续的任务，并明确把交互判断交给格得，不要求机械新增按钮或 tab。

## 决策

把“待我输入”作为现有列表的收件箱视图，复用同一份原任务、行组件、详情和草稿。

- 电脑：左侧导航首项，和全部任务、置顶并列，显示数量。普通列表工具栏不再重复放同名入口。
- 手机：列表页保留一个44px的一键入口，减少打开抽屉的步骤。进入后同一位置变为“返回列表”，避免与标题重复。
- 范围：查看所有未归档顶层任务，不受之前的置顶、项目、分组和搜索限制。否则用户在一个窄范围里会漏掉其他地方的待输入任务。
- 进入时暂存原视图、项目、搜索展开状态/搜索词、排序、滚动位置及选中的任务；清除范围限制，默认按最近活动查看。返回后恢复原上下文和现有草稿，不主动弹出键盘。
- 普通列表中的符合项也显示蓝点；不改变分类、分组，不复制任务或引入新的待办承诺。

这是“查看需要接续的任务”与“浏览整理全部任务”的切换。它没有另建第二套任务系统。

## 搜索和排序

搜索默认只有放大镜。点击时同步展开并聚焦，输入框16px；关闭或非输入法组合中的 Escape 会清空并收起，Ctrl/⌘K 可直接展开。Enter结束搜索输入，组合输入的Enter/Escape不提前打断。

排序保留最近活动、置顶优先；删除按标题、回顾日期选项，旧设备偏好自动回到最近活动。原有回顾日期记录和稍后继续功能保留。

## 状态与边界

使用 Codex 原始未读集合，限定已核验的当前身份/主机；再用匹配原任务的有界 rollout 生命周期确认已经结束。普通idle、原未读=false、仍未确认结束、归档/分隔/来源缺失不计入。原标记无法读取时显示未知，不伪装成0条。详见 [原始证据](../research/2026-09-29-unread-status.md)。

该名称沿用用户要求，但状态是“原未读提醒且已结束”，不是AI自行判断用户必须继续。09-29 首版只读取状态；2026-10-05 已接入[阅读后同步原已读](2026-10-05-read-state-sync.md)，当前可见内容确认后清除蓝点，列表移除而详情和草稿保持。开始新一轮会暂时离开这个视图，结束后仍取决于原未读状态。其他桌面变化按现有前台刷新/返回/手动刷新流程同步，不宣称毫秒级镜像。

当前适配为 API-key + local stdio；其他身份/连接形式需重新核验。只有少量原未读的顶层候选会被读尾，256KiB上限、session_meta身份校验、限定sessions路径、文件变化失效缓存，不逐任务调用IPC。
