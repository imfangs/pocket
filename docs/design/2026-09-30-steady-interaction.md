# 刷新、草稿与底部阅读的连续性

2026-09-30 方帅要求继续把 Pocket 做得更好。本轮从已有使用流程中复现三个问题，修复现有能力，不扩大原任务控制范围或落实尚未讨论的调研候选。

## 修复与复现

| 流程 | 修复前的确切行为 | 修复后 |
| --- | --- | --- |
| 初次加载中切回前台 | 后发的 sync 已成功，但列表仍等旧 GET；旧 GET 晚到会覆盖更新标题 | 最新成功的请求直接结束加载；旧数据和旧错误不能覆盖新结果 |
| 保存接续说明时后台刷新 | 保存响应返回新 revision 后，早先的目录仍能覆盖它，详情恢复旧说明 | 成功保存、打开、批量整理、导入都使此前目录读失效 |
| 发送后离开并重进 | 编辑新草稿 B 后，旧提交 A 的 accepted 或 409 回来，会改写共享草稿 Map；当前框看起来还在 B，再次重进却丢失 | 回执需同时匹配仍存活的视图、当前 controller 和原 requestId 才可修改草稿 |
| 输入由两行长到二十行 | 消息容器缩短，最新尾部被挤出 182px，直到后续轮询才回到底部 | ResizeObserver 在已跟随底部时同步位置；向上阅读时不抢位置 |

目录失败保留已有列表并显示简短重试入口；成功恢复后自动清除该读取错误，与普通操作错误分开。已淘汰的刷新不会弹出“任务已刷新”。

离开任务只取消前端回执读取，不取消或重发已提交操作。重新进入且保留原草稿时仍可使用原 requestId 做一次只读 GET 核对。未知发送仍不自动重发，执行权限继续只来自原桌面状态。没有新增草稿持久化、外部缓存或源数据写入。
