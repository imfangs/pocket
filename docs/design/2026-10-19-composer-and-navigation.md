# 输入区收拢与独立筛选

2026-10-19。用户连续提出：消解会话标题下工具栏；菜单显示分类/项目数量并把分类名缩为「全部 / 关注 / 置顶」；范围与状态/排序应能叠加；统一「待我输入 / 未读」用词。本轮合并实现和验证，不改原会话执行协议。

## 会话详情

- 删除标题下的独立工具栏。正文直接接在标题后，空闲时不再重复显示「可继续」，同一输入框的「继续对话…」和发送动作表达可继续。
- 运行、等待确认、已中断、上次出错及必要用时放进输入区；停止/停止结果核对仍可操作。已完成用时继续与消息footer去重，缺少可显示该时长的final时保留原兜底。
- 上下文入口在输入区底部，常态只显示圆环与百分比；可访问名称仍说明上下文。点开向上浮层，查看token数量并执行压缩/核对。
- 删除常驻刷新按钮，自动读取和前台恢复保持。读取失败时在错误旁出现「重新读取」；连接失败和未知发送继续走原有主按钮，不重发未知消息。

ContextStatus和StopExecution始终挂载，保留本地未知requestId及reload保护。浮层打开、压缩/停止处理中或待核对时维持展开；指针按下不提前抢焦点，避免紧凑输入展开使首点落空。指针关闭浮层后可恢复紧凑阅读，键盘关闭仍回到触发按钮。Portal遮挡期间保留已读与预连接保护。

编辑待发消息时仅隐藏普通草稿输入、附件选择和发送按钮，不再隐藏整个composer；运行状态、停止、上下文及其未知回执继续可见。原textarea节点、草稿、队列状态和权限保持。

## 菜单与三个维度

菜单的「全部 / 关注 / 置顶」和各项目显示完整范围内的会话数量，包含0；同名项目按ID分别计数，双标记会话分别计入关注和置顶。计数使用一次遍历，不按每个项目重复排序。来源失败沿用已有catalog，不能凭失败造0。已归档继续沿用用户此前要求，不显示菜单数量。

列表状态分开保存：

| 维度 | 选择 | 行为 |
| --- | --- | --- |
| 范围 | 全部、关注、置顶、项目、已归档 | 标题始终显示这一维；菜单切换保留状态和排序，按原约定清搜索 |
| 状态 | 无、未读、运行中 | 在当前范围和搜索内筛选，取消只清本维度；两个状态互斥 |
| 排序 | 智能、最近创建 | 可与范围、状态及搜索叠加；取消最近创建只恢复智能排序 |

例如「关注 + 运行中 + 最近创建」只显示关注的运行会话，按创建时间倒序，标题始终为「关注」。筛选按钮的数字反映当前范围与搜索下的结果，菜单数字不受筛选和搜索影响。归档清除无意义的活动筛选，但可按创建时间排序。空筛选结果可原地取消该筛选，不暗中切到全部。

偏好升级为v4的`scope/project/activity/sort`，仍按机器隔离。v3的unread/running/created迁移为对应维度，保留实际存下的project；旧版只存在内存中的returnView不可能跨刷新恢复，不推测未保存的范围。列表按范围/项目/状态/排序/搜索组合维护滚动和按压保护，防止不同组合串用旧行。

## 统一未读

筛选和列表统一叫「未读」。原生明确已读（hasUnreadTurn=false）优先；已读但等待回答/确认不因此变为未读，仍显示独立等待状态并保留注意力排序加分。真正未读且等待操作时，两种标记可并列。

继续保留原“结果可读”边界：运行中不纳入未读；旧缓存缺少结束证据时，不能只凭hasUnreadTurn=true就认作可读的未读结果。原needsInput可兼容缺少hasUnreadTurn的已确认结束旧快照。没有更改原生已读广播、原会话状态或Rank权重，也不把该列表描述为完整复制Codex所有蓝点。
