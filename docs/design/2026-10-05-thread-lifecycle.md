# Pocket 新建、归档与恢复

2026-10-05。方帅明确要求让新建和归档会话在 Pocket 可用。

## 使用

- 列表头部点「新建会话」，选择已存在的工作目录，可选名称；创建完成后进入该会话。首条消息点「发送并连接」，仍由原桌面 owner 执行。
- 详情「整理」页提供「归档会话」和「恢复会话」。普通草稿、接续说明、分组及分类保留；普通列表不再列出真实已归档任务，归档视图仍可查找。
- 没有 writer 占用的已结束会话或空会话可以立即归档。归档包括原 spawned 子树；恢复只恢复指定主会话。
- 已结束但仍被 Codex 占用的会话显示「等待 Codex 释放会话」，持久保存请求并支持取消。未完成前原 archived 标志保持真实状态。请求期间有新内容或子树变化时停止本次归档，避免以后误归档新工作。
- 有待发正文、正在提交的消息/审批/压缩等操作时先处理现有操作。归档不删除待发正文，也不隐式停止模型。

普通空会话创建后不立即打开 Mac，用户可以直接归档尚未开始的空会话；第一次发送复用连接恢复与防重回执。此前只验证了留空name，没有验证自动拟题触发。2026-10-09已补齐原owner首发的命名参数并完成真实命名回读，见[原生命名](../research/2026-10-09-native-initial-title.md)。

2026-10-09入口优化：目录查找默认收起，当前设备记住上次明确选择的目录及项目，并用最新选项重新校验。标题留空时仍省略name字段。成功创建提示累计可见8秒后自动收起，未决和错误状态保留；交互、回归和自动命名验证边界见[新建与发送反馈](2026-10-09-creation-and-send-feedback.md)。

## 官方创建路线

最初验证固定桌面包CLI `0.153.4` 与App `26.903.71938:8576`。2026-10-10已更新到App `26.1007.21159:20052` / CLI `0.162.0-alpha.17.2`，重新完成隔离空home的持久化、归档和恢复验收；新旧打包路径按精确已验证版本在 `bin/bundled_cli.py` 解析，当前启用版本以 `config/desktop-bridge.json` 为准。PATH上的其他CLI不作为依据。见[升级兼容](../research/2026-10-10-desktop-upgrade-compatibility.md)。

通过短生命周期官方 stdio 进程 `thread/start(ephemeral:false, historyMode:paginated)` 创建空会话。该版本必须显式物化空历史；带名称时 `thread/name/set` 后 `thread/read(includeTurns:true)` 可完成。无名称时，仅对固定版本的精确 `-32601 / list_turns is not supported yet` 分支继续核验：该调用已物化 session_meta，退出 creator 后另起官方 metadata-only read 补齐索引。其余错误不能当成功。

若选择了原项目，使用官方 `thread/metadata/update` 持久化 projectId。最后停止两个短进程，再独立核对 SQLite、原 ID/cwd/project、只有 session_meta、零用户事件和零 tokens；名称未填写时保持原 name=null，不强行命名“新会话”。本机模型、provider、审批与权限继承现有配置，没有启动模型轮次。

请求开始前先保存私有 checkpoint，拿到 ID 立即保存；相同 requestId 只核对同一回执和原 ID，不重复 thread/start。未知且没有 ID 时不新建第二条。实现与隔离回归在 `bin/create-thread.py`、`tests/create-thread-protocol.test.mjs`；研究证据 `.local/qa/empty-thread-research-2026-10-05/`。

## 归档与占用

`bin/archive-thread.py` 只读原 SQLite、rollout 与 writer 锁，用官方 CLI 完成归档/恢复；不直接修改 Codex 文件、不删除锁，也不发送虚假的 thread-archived 广播。

归档 fingerprint 绑定精确 root、全 spawned 子树的 ID、原归档状态、historyMode、内容 SHA 与字节数；不包含锁或 mtime，所以正常释放 writer 不会使请求失效。每次实际调用前再核对树、正文和真实锁，写后独立核对全树归档状态及原 SHA。root 已归档但子树不完整时明确报告 partial_subtree，不误报整次成功。

恢复只检查、修改和核对 root，不受缺失或正在活动的子任务影响。归档全树 fingerprint 与恢复 rootFingerprint 不混用。命令退出码和广播均不代替独立回读，模糊结果保留 unknown。

等待期间 Pocket 停止目标及子树的 owner 快照、连接恢复、派发与通知检查，正文仍可从保存历史读取。取消和后台 worker 按请求串行，取消完成后不会继续归档；已有原生写入则先核对实际状态，不把取消解释成撤销归档。

**当前原生限制（10-15复核）**：普通follower IPC仍没有按ID归档/卸载入口。当前App的闲置owner保留期已为3小时，且有活动视图、follower或需保留状态时不进入释放候选；实际writer释放还取决于原App Server状态，不能承诺固定时长。10-05最初记录的renderer 1小时及后端30分钟仅为当时版本观察，不能继续作为当前预计等待时间。Pocket不重启Codex、不打断其他会话、不删除锁或绕过宿主签名边界。

共享 WebSocket 迁移会跳过当前 App Tools MCP 注入和原 owner/read-state IPC 注册，影响刚验证的发送、审批与已读同步，不作为本轮隐式替换。原始入口依据见 [09-29 控制面研究](../research/2026-09-29-desktop-control-entrypoints.md)。

## 状态与恢复

`lifecycle_operations` 与创建回执保存在 Pocket 私有数据目录。API 使用稳定 requestId，状态为 pending、waiting、succeeded、rejected、unknown、cancelled、changed。

客户端刷新后重新读取原操作；只有成功回读才更新真实归档状态。创建结果晚到时保留“打开新会话”入口，先保存当前整理内容再切换；不会抢走用户已选择的另一个任务。创建恢复的 sessionStorage 仅保存未决/待领取成功的 requestId，明确拒绝不会变成永远占位的 unknown。

确定尚未启动的创建失败直接拒绝；无法核对的 unknown 创建可明确「停止核对」，只停止 Pocket 跟踪，不删除任何可能已创建的会话，也不重新提交同一创建。pending 创建仍不能中途撤销。

## 2026-10-15 持锁子会话导致长期等待

用户报告归档反复提示忙碌。只读核对最近两次已取消的请求：主会话已结束且无writer锁，3个已结束的spawn子会话仍由原App Server持锁，4个节点的archived均为0。不能把writer占用误说为模型仍运行，也不能自动重放用户取消的请求。用户随后明确选择先保留。实际ID仅留私有证据，不进入本文。

当前App为26.1007.71326:20398、CLI为0.162.0-alpha.17.2。在完全隔离的临时home中，0用户事件/0tokens的官方协议对照证明：持锁时独立CLI归档失败，同一owner的thread/archive立即成功并释放锁。父无锁、子由另一测试owner持锁时，短RPC和CLI均被子锁阻止；释放后两条路线均递归归档整个子树。因此仅改成短RPC、跳过子锁或改root-only预检都不能解决，也不能默默缩小归档语义。

原生桌面工具走其自身manager→thread/archive，并处理pin/缓存/广播等桌面状态。当前Pocket独立进程没有已核验可调用此宿主通道的入口：原Core为stdio，无对应control socket；官方proxy需要现存同owner端点；AppTools MCP包装仍要求宿主上下文和签名peer，不能用解释器或假身份绕过。没有因此更改任何真实Codex存储或进程。

本轮只修正等待文案为“Codex仍占用会话，释放后继续归档/恢复”，保留原请求编号、取消和真实状态核对，不声称修复了原owner接口缺口。**当前支持的是无占用时的归档及可取消等待，不能承诺手机立即归档所有已结束会话。** 后续需受支持的原owner控制入口才能补齐。

实证入口：`.local/qa/archive-owner-2026-10-15/proof.json`与`subtree-proof.json`；源版本和提示回归在CURRENT。所有测试owner和临时home已清理。

2026-10-16继续研究“下一次启动时共享原Core”的接入方案，区分普通WS迁移、官方raw proxy与保留桌面父链的stdio适配器；当前产品限制没有因此自动解除。新证据、原型结果及真实GUI验收边界统一见[归档owner路线](../research/2026-10-16-archive-owner-route.md)。

## 2026-10-18 取消归档入口

用户希望在 Pocket 找到已归档的会话并发起取消归档。底层已有恢复能力，但390px手机浏览器复现：有历史、没有草稿时，输入区收成紧凑模式，CSS连同可用的恢复主按钮一起隐藏，必须先聚焦输入框才能发现。本轮把归档状态纳入输入区必须展开的反馈，进入归档详情即显示操作，不要求先输入或唤起键盘。

同时统一可见名称：菜单与列表标题使用「已归档」，详情右下主按钮及会话信息中的动作使用「取消归档」和归档恢复图标，输入占位说明需先取消归档。操作中、等待、成功、失败及重命名提示采用同一说法。

路径为「菜单 → 已归档 → 打开会话 → 取消归档」。成功仍停留在原会话，保留原 ID、正文及 Query 草稿；会话从归档列表移回普通列表，不自动连接或发送。聚焦、输入和阅读历史都不会发起取消归档。只恢复指定 root，已归档子会话保持原状。已有 requestId、未知只读核对与 writer 等待/取消契约不变；没有新增管理页或第二套后端操作。

本机 CLI `0.162.0-alpha.17.2` 的隔离复核确认：已归档、旧生命周期 unknown 且无 writer 的 root 可以恢复；真实独占锁下 Pocket 等待，官方 unarchive 同样失败，释放后成功。因此不放宽 writer 守卫，也不把本次入口完善描述成已解决原 owner 归档限制。所有复核对象均为合成或临时 home，没有改动用户已归档的真实会话。

## 2026-10-20：创建默认设置

空会话物化后，通过官方thread/settings/update保存创建响应中的有效model/effort，独立回读一致才允许首条Query进入队列。未知仍只核对，恢复不重建、不重发设置；本机0turn/0tokens协议验收已通过，细节与发布事实见[新会话默认强度](2026-10-18-model-settings.md#2026-10-20新会话保留默认强度)。

实际新建验收发现，原归档器将任何header后的记录都当成非空，使新增设置元数据触发active_or_unknown。现将“空”限定为完整rollout只有初始化与合法同ID的thread_settings_applied、0用户事件和0tokens；设置记录按完整行解析，总2MiB/单行1MiB有界，原全文件SHA、双读稳定检查、writer、子树和fingerprint保护保持。仅设置元数据的resumed空会话因此可以归档；包含turn_context、轮次开始、消息、坏记录或超限内容的未知会话仍不能凭零计数归档。这是对10-17旧resumed-empty保守取舍的具体收窄。
