# Pocket 深度设计评审

2026-10-09。基线：`a62fb635c39b479c0399148b9c0c0394e4f233bc`，产品源码 `0735e16`。本轮是分析；以下方案尚未实施，也未发布。按标杆设计方法核对当前代码、390×844 实际渲染的合成场景与官方来源。

## 产品判断

Pocket 最值得达到的体验是：打开后很快知道什么需要自己处理、哪些任务还在执行、上次看到哪里；完成一次回应后，可以放心离开。

现有暖白/炭色、标题优先、克制的分隔线、正文与整理分区已经形成一致基调。下一轮品质提升应围绕注意力分配、操作反馈与接续连续性。视觉上进一步突出当前动作、降低重复信息的权重，沿用现有主题与触控基础。

本轮直接看过列表、长回复末尾和新建表单的受控截图：列表层次清楚，但时间、项目、手工安排、执行状态集中在行内，运行任务可能处于首屏外；阅读页顶部与回复末尾重复显示用时；新建的首个焦点仍是目录搜索。后两点是改善候选，不单凭截图判为缺陷。

## 优先级与适配决定

### 1. 让“需要我处理”与“有新进展”各自准确（最高优先）

**当前问题。** `server/source.mjs:105` 将 `needsInput` 定义为未读且轮次已结束，`src/model.ts:54` 的待输入视图仅据此筛选。新增的原生等待状态只改变行内显示，尚未进入筛选。在合成场景中，“周末的城市漫游计划”显示等待回答，但未读为false，点击“待我输入 2”后该任务被排除。这是浏览器复现与代码相互印证的语义缺口，未据此断言某条真实任务已经遗漏。

**决定。** 借鉴 Linear 区分注意事项与其他更新：列表头部提供紧凑的“需处理 / 运行中 / 新进展”入口，保留全部会话的原排序。需处理依据仍有效的原问题/审批；阅读只清未读，响应被原任务确认或问题过期后才移除待处理。运行状态从有界候选确认，未知和候选外不能算空闲；摘要必须保留覆盖不完整与更新时间的表达，0不能承诺“全部空闲”。这需要轻量状态投影，不能轮询所有任务的完整正文。

**预期与检查。** 打开Pocket即可找到已确认的待处理任务和运行任务，不用在历史中逐行扫描。测试“已读未答、运行中审批、响应未知、问题已解决、状态过期”；人工检查找到目标所需操作与误判。当前合成运行任务在第8行，行顶y=835，状态位于390×844首屏外，作为对照基线。

### 2. 把已提交内容、回执和下一条草稿分开（最高优先）

**当前问题。** `src/Conversation.tsx:311` 通过 `draft.requestId` 决定核对旧提交；等待回执期间输入被禁用（500）。结果未知后修改文字会用仅含text的新对象替换草稿（501–502），按钮由核对切回发送（515）。普通直接发送的unknown不一定具有待发正文卡。这不等于已经发生重复发送，但用户可能难以辨别自己正在修改草稿还是开始一条新请求。

**决定。** 采用 Apple 的稳定位置与准确反馈原则：提交文本成为独立消息卡，显示“正在提交 / 等待确认 / 原任务已接收”等事实；输入框用于下一条草稿。旧消息保留核对入口，新草稿不覆盖其身份。沿用防重ID、迟到回执保护与未知时先核对的约定；入队、接收和模型完成保持不同含义。

**预期与检查。** 慢网络下仍能继续组织下一句话，并能随时找到上一条的结果。以长延迟、断网、unknown后编辑、切任务、重连和迟到回执验证；检查用户能否说清“上一条有没有收到、下一条是否已经发出”，同时保持单次派发。不能只解除输入框disabled就算完成。

### 3. 建立可信的“最近访问”与阅读接续（次优先）

**当前问题。** Pocket行点击只选择任务（`src/App.tsx:586`）；`lastOpenedAt`仅在“在Mac打开/连接”接口写入（`server/index.mjs:352`），最近视图仍按任务更新日期排序（`src/model.ts:57,75`）。合成浏览器中读完一条任务后，“最近打开”仍为0。正文已保留像素位置和近底部状态，但位置随10条正文缓存一起淘汰（`src/conversationFeed.ts:60,75`）；宽度、图片和正文补齐会改变像素对应的内容。首次打开长回复默认到最末尾（`src/Conversation.tsx:235`），当前只提供返回最新。

**决定。** 借鉴 Notion 最近访问与明确查找范围：单独记录Pocket真实访问时间并据此排序，搜索未输入时提供最近访问，关键词可明确扩大到全部任务，局部筛选保留。正文位置采用轻量消息ID与内部偏移；提供“从新内容开始 / 查看本轮回复”的明确锚点。首次未读边界无法可靠确定时，不虚构“从这里未读”；可以先支持最新最终回复的开头。过程仍完整可读，滚动与已读权威保持独立。

**预期与检查。** 用户离开再回来可接着看，不必重新寻找任务和段落。验证纯手机阅读旧任务出现在最近首位、局部搜索扩大范围后返回、超过10条缓存后返回、图片加载和宽度变化；确认草稿、原筛选和当前阅读位置不丢。全局查找第一版可复用现有标题/项目/说明/分组范围，不冒充全文搜索。

### 4. 让连接与管理动作有清晰的影响和收尾（次优先）

**当前问题。** 重连与“在Mac打开”共用 `onOpen`（`src/Inspector.tsx:253`），默认恢复会先打开原任务（`server/desktop.mjs:104`）；手机只想恢复连接时可能切换Mac当前任务。归档已有持久等待和取消，但等待卡没有回访任务入口，完成后也会离开全局提示集合（`src/TaskOperationStatus.tsx:16`、`src/useTaskOperations.ts:108`）。

**决定。** 重连先核对已加载owner，必要时再按现有能力打开；显式“在Mac打开”保留主动切换意图。将归档等待与完成留在同一操作卡，提供可回访入口和准确的取消文案。查看等待对象仅显示已有内容，不能重新订阅而妨碍归档。正常态保持轻量，只有需要行动时展开原因和一个主操作。

**预期与检查。** 用户知道动作影响哪里、完成后去哪找结果。验证已加载owner重连零open调用；未加载仍可恢复；归档跨任务、刷新、完成及取消竞态不抢焦点，不错误恢复发送。此项目前为代码审查，未操作真实Mac任务验证。

### 5. 把新建变成更自然的起笔（较后，先做原型）

**当前问题与假设。** 目录搜索、去重和共享项目消歧已经交付。目前先选择位置并创建，再进入空会话写第一句话。对手机临时想到一件事的场景，先选目录可能打断表达；这属于设计假设，尚无用户效果证据。

**决定。** 原型可以先承接第一句话，将明确的工作目录/项目放在相邻上下文区域，可沿用当前项目并显式修改。执行前仍必须核对准确locationId，共享目录保持明确项目选择。借鉴Notion低负担起笔，同时保留Pocket的执行目录约束；创建与首发是两个可能独立失败的步骤，不能包装成不可恢复的黑盒。

**预期与检查。** 比较记下第一句话的时间、目录选错率与取消后的草稿恢复。未知创建不重复创建，未知首发不重复发送。先验证收益，再决定是否替换当前表单。

## 建议的下一轮范围

第一轮完成第1、2项，带上第3项中的真实访问记录；它们对应本次已确认的注意力与操作反馈缺口。第二轮再做阅读锚点、全局快速定位、连接和管理收尾。新建输入优先先以原型比较。

视觉随这些行为一起调整：列表行将实时动作状态作为主要辅助信息，普通项目/安排保持次要；正常阅读弱化重复用时，稳定保留正文与回复区；等待、失败和确认采用同一套位置与语言。检验重点是能否更快且准确地理解当前状态、找回任务和完成回应，实际收益仍须用户使用验证。
