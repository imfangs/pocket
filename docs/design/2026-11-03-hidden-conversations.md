# Pocket 会话隐藏

2026-11-03。用户希望左滑列表项后点击“隐藏”，从日常列表移出，并能从菜单里的“隐藏”分类找回。

## 交互

- 左滑继续显示蓝色“优先关注 / 取消关注”，旁边增加灰色“隐藏”；每个动作84px。隐藏分类里相同位置改为“取消隐藏”。桌面悬停及键盘同样可操作。
- “隐藏”是两字菜单分类，显示数量。进入时清空无关项目/活动筛选，保留排序选择；可以搜索，默认按最后消息时间查找。
- 普通全部、项目、关注、置顶、未读、运行中和归档列表都排除隐藏项。“隐藏”分类包含已隐藏的普通和归档会话；取消隐藏只恢复对应列表可见性，不取消归档。
- 两个行操作共用保存门禁。确认保存后移除行并释放该行的交互暂存；失败保留原行和轻量重试说明。切分类或输入后，迟到结果不抢键盘焦点。
- 不改变原会话的运行、归档、关注、未读、消息或草稿。隐藏的会话仍可以通过已知深链打开，隐藏不是访问控制。

## 状态与协议

- 状态保存在目标电脑的Pocket SQLite `hidden_threads`，两个电脑分别持有自己的偏好；不是Codex自身的隐藏或归档字段。
- `POST /api/tasks/:id/hidden`接受`{hidden:boolean,scope?:string}`，新客户端传入发起时的来源scope；不一致时409且不写入，成功返回完整会话及`visibilityScope`。幂等设置显式目标，沿用认证、同源及CSRF检查，不调用原生桌面操作。
- `pocketHidden`与独立单调`hiddenRevision`一起返回；目录仍包含隐藏记录，以便隐藏分类读取。原sourceExcluded边界优先，隐藏分类不绕过桌面来源范围。
- version 1备份增加可选`hiddenThreads`：旧备份缺字段保留当前偏好，显式空数组清空；恢复改变时推进修订号。源同步、归档和后台活动不会取消隐藏。
- 写入结果丢失时只读核对，不自动重复切换。动作绑定发起来源scope，冷缓存先核对当前目录；过时scope的结果不能合入新来源。
- 阅读缓存保留完整隐藏投影。同电脑/来源下，目录基底仍沿扫描时间选择，独立hidden/title/pin修订分别合并，防止旧快照或另一标签的迟到写入回滚隐藏。来源/认证fence及缓存容量保护继续生效。
- 刚创建会话的列表提升不会绕过隐藏；隐藏项也不占用后台正文预取的候选额度。
