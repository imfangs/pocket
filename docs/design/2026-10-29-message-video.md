# 会话视频展示与播放

2026-10-29。用户提供一个Pocket会话，其中助手通过Markdown图片语法展示本地MP4，希望在手机端直接观看。实际样本为3秒H.264、1080×684、约1 MiB的对照视频。实现与边界记录在本页，已部署版本以CURRENT为准。

## 观看方式

助手可见回复里的本地MP4/M4V/MOV/WebM引用共用原生播放器：支持Markdown图片语法、普通文件链接和Codex文件引用。保留视频说明，使用`controls`、`playsInline`和`preload=none`，不自动播放或先读整片到Blob；原生控件负责播放、进度和全屏。固定画框内完整显示，不裁切原画面。

点击另一个视频会暂停前一个；离开页面、切换会话/机器或卸载时暂停并移除媒体源。流式追加正文不重建同一视频节点。失败在原位置提示重试，并可下载原文件；下载也走受控流，不在前端缓存整段视频。

仅支持浏览器能够解码的编码组合，MP4/H.264为本轮真实验证对象。容器签名通过不等于所有编码均能播放；不在服务端自动转码，不引入第三方播放器。外站视频仍是显式链接，不因阅读私人会话自动请求外站。

## 文件授权保持

- 复用现有`files[path] = {name,url}`，消息与阅读缓存schema不变。签名地址仍绑定thread和cwd，客户端不能指定任意路径。
- 服务端仅从完整、可见的assistant正文登记。新视频支持image/imageReference；代码/转义示例、HTML、未知组件、隐藏引用与memory provenance不签发文件能力。重复Markdown定义采用首条，与显示一致。
- 包在链接里的视频image保留为链接标签，不在`a`中生成原生交互播放器；该内部image本身不签发视频能力，同路径在别处已登记也不能改变这一呈现规则。
- 普通PNG/JPEG等沿原图片通道；普通文件的20 MiB下载约束保持。未登记或不可访问的视频仅显示安全回退，不凭文件后缀授予权限。

## 分段读取

`GET/HEAD /api/tasks/:threadId/files/:key?video=1`使用新的视频流路径；加`download=1`返回附件处置。新通道重新验证真实目录、普通文件、容器签名、文件身份及512 MiB上限；只允许MP4/M4V/MOV/WebM，额外查询参数不能替换路径。最大16路活跃GET，64 KiB分块与背压，关闭/取消后回收FD。HTML、SVG等不作为媒体执行。

支持单Range、后缀Range、开放结尾范围、206与416；HEAD只返回完整元数据。返回Accept-Ranges、Content-Range/Length、强ETag、Last-Modified，以及no-store/nosniff/same-origin策略。If-Range只有精确强ETag匹配才续传；日期、weak标签或不匹配的校验回完整200，避免秒级修改时间无法证明旧片段身份。

流期间检查文件身份和路径变化；响应头发出后若失败，终止流而不是混入JSON错误。Worker只在视频路由转发Range/If-Range，保留机器身份和Cookie隔离。20秒仅约束等待上游响应头，不会截断健康的视频正文；取消与拒绝错误上游时关闭传输。媒体仅从同源加载。

API收到停机信号时先中止视频流并拒绝新视频请求，再等待原有非视频请求结束，避免暂停的大视频连接阻止正常更新。取消发生在响应头之前也会关闭response；HTTP/FD各关闭一次的竞态已做回归。
